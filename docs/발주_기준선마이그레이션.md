## 0. 한 줄

**빈 개발용 Supabase 프로젝트에 `engine` 스키마를 처음 세우고, 그 절차를 다시 돌릴 수 있는 형태로 repo에 남긴다.**

지금 `supabase/L0_스키마.sql`은 **한 번 붙여넣으면 서는 파일**이지 마이그레이션이 아니다. 두 번째 변경부터는
`create table if not exists`가 통째로 건너뛰어서 **아무 일도 안 일어나는데 초록으로 보인다.** 그 성질을 파일 스스로
경고하고 있으나(헤더 ⚠), 경고는 아무것도 막지 못한다.

## 1. 왜 지금인가 — 되돌릴 수 있는 마지막 지점

- 실학생 **0명**이다. 빈 DB에 잘못 세우면 지우고 다시 세우면 된다. 개원(2027-02) 뒤엔 그 선택지가 사라진다.
- 계약은 **c4에서 동결**됐다(2026-08-06 · `계약/수집_교정_계약.json`). 기준선이 **처음부터 c4로 태어나면
  `alter table` 이행 자체가 안 생긴다.** c3로 세운 뒤 올리는 것보다 싸고, 「조용한 미적용」 위험이 0이다.
- S1(첫 앱 화면)의 남은 전제가 이것 하나다.

## 3. 산출물

### 3-1. 커밋된 마이그레이션 (필수)

`supabase/L0_스키마.sql` 하나로는 두 번째 변경을 못 싣는다. **적용 순서가 파일에 드러나고 재실행이 안전한 형태**로
정리한다. 구체적 배치(디렉터리·파일명 규칙·Supabase CLI 채택 여부)는 **Codex가 정한다** — 아래 제약만 지킨다.

- **① 순서가 이름에 있다.** 나중에 온 사람이 실행 순서를 추측하지 않는다.
- **② 재실행이 안전하다.** 두 번 돌려도 에러가 안 나고 데이터를 안 지운다. ⚠ 단 **「안전」과 「반영」은 다르다** —
  재실행으로 반영되지 않는 변경(제약 이름·CHECK 값)은 별도 문장으로 적는다.
- **③ 유호님 실행 경로는 「SQL Editor에 붙여넣고 Run」을 유지한다.** 🔴 **유호님께 CLI·Docker·터미널 설치를
  요구하는 안은 반려 사유다** — 비개발자이고, 도구가 하나 늘면 그날 막힌다. CLI를 쓰려면 **AI 쪽에서만** 쓴다.
- **④ 기준선은 c4다.** 제약 이름 3개 = `learning_events_event_type_c4` · `learning_events_task_type_c4` ·
  `corrections_verdict_c4`. 값목록은 계약 파일에서 파생시킨다(손으로 옮기지 않는다).

**⑤⑥⑦은 적용 주체 A 확정(§6)에서 나온다** — 「사람이 손으로 실행한다」의 귀결이라 A인 한 협상 대상이 아니다.

- **⑤ 유호님이 붙여넣는 것은 1개다.** ①에 따라 파일을 여러 개로 쪼개는 것은 좋으나, 그 경우 **순서대로 이어붙인
  합본 1개**를 함께 산출한다. 유호님은 합본 하나만 붙여넣는다. 🔴 **파일 개수·실행 순서를 사람이 기억하게 하는
  안은 반려 사유다** — `docs/L0_데이터계약.md` §8의 클릭 절차 4번이 「전문을 복사해 붙여넣기」 **1회**를 전제한다.
- **⑥ 그 §8 클릭 절차를 새 경로로 고치는 것까지가 산출물이다.** 지금 4번은 `supabase/L0_스키마.sql`을 가리킨다 —
  배치를 바꾸고 절차를 그대로 두면, 절차가 **조용히 틀린 파일을 가리킨 채 초록으로 보인다.**
- **⑦ 실패했을 때 유호님이 할 일을 정의한다.** 유호님은 **아무것도 고치지 않는다**(L0 §8 「편집창 즉석 수정 금지」). 실패 시
  행동은 「화면의 빨간 문구를 그대로 AI에게 전달」 하나뿐이고 복구는 AI 몫이다. 그래서 **그 오류 문구만으로
  어디까지 적용됐는지 판별 가능**해야 한다(§3-2 ③ 중간 실패와 같은 축 — 사람이 DB를 뒤져보는 복구는 불가).

### 3-2. 검증 5종 — **실행 층**에서 (필수)

지금 회귀 8건은 전부 **SQL 텍스트를 읽는** 검사다. 파일이 문법적으로 맞는지도, 진짜 DB에 서는지도 모른다.
아래는 실제로 돌려서 확인한다. **운영 후보 프로젝트에서는 하지 않는다.**
⚠ 어디서 돌릴지는 열려 있지 않다 — **아래 「실행 층이 지금 없다」를 먼저 읽어라.**

| # | 항목 | 통과 기준 |
|---|---|---|
| ① | **빈 DB 적용** | 아무것도 없는 DB에서 끝까지 완주 · 확인 쿼리 `판정` 칸 = `✅ 전부 통과` |
| ② | **재실행** | 같은 것을 다시 돌려 에러 0 · 데이터·구조 변화 0 |
| ③ | **중간 실패** | 임의 지점에서 끊었을 때 **반쪽 상태가 남는지** 확인하고, 남으면 그 사실을 문서화(트랜잭션 경계) |
| ④ | **롤백** | 세운 것을 되돌리는 경로가 실재하는지 — 실행해서 확인. 없으면 그것도 결론이다(「전진 수정만 가능」) |
| ⑤ | **RLS** | 학생 토큰으로 **남의 행이 안 보이고**, 학생이 **쓰기를 못 하며**, `anon`·`authenticated`에 `engine` 권한 0 |

⑤는 문서가 이미 정한 계약이다(L0 §4-3 · C0 §1). **정책 파일을 읽어 통과라고 하지 말고 실제 토큰으로 조회한다** —
정책은 있는데 안 먹는 형태가 이 저장소가 여러 번 데인 자리다.

#### ⚠ 실행 층이 지금 없다 — 발주 시점 실측 (2026-08-06 · 이 발주의 최대 차단자)

유호님 PC에 **`docker`·`psql`·`pg_ctl`·`supabase` CLI가 전부 없다**(4종 모두 `MISSING` 실측). 그리고 A 확정(§6)이라
AI는 Supabase 자격증명을 갖지 않으므로 **「임시 프로젝트」 경로도 AI 단독으로는 막힌다.** 즉 위 5종을 돌릴 자리가
**현재 존재하지 않는다.** 착수하면 바로 여기서 멈춘다 — **먼저 고르고, 고른 뒤에 움직인다.**

- **(가) 로컬에 Postgres를 세운다** — AI 쪽 도구이므로 §3-1 ③ 위반이 아니다. 🔴 **단 유호님 PC에 무언가를 설치하는
  것은 유호님 승인 사항이다** — 무엇을·용량·되돌리는 법을 적어 클로드를 거쳐 올린다. 임의 설치는 그 자체가 결함.
- **(나) 유호님이 개발용 프로젝트에서 검증까지 실행** — 자격증명이 0으로 유지되는 대신 왕복이 늘고, 붙여넣기가
  5종만큼 반복돼 **§3-1 ⑤와 정면으로 부딪힌다.** 채택하려면 ⑤를 어떻게 지키는지 같이 낸다.
- **(다) 검증 층을 줄인다** — 🔴 **클로드 판정 사항이다.** 의미 층 경계(§5)라 Codex가 단독으로 줄이지 않는다.
- **(라) 넷째 길** — 예: **CI 러너의 Postgres 서비스에서 돌린다.** 유호님 PC를 안 건드리고 자격증명도 안 쓰며,
  검증이 **회귀로 남는다**(§4-2가 요구하는 것과 같은 자리). `.github/workflows/ci.yml`의 `verify` 잡은
  `ubuntu-latest`에서 돌아 서비스 컨테이너를 붙일 자리가 있다(클로드 실측) — **읽어서 직접 확인해라.**
  ⚠ **함정**: Supabase의 RLS는 `auth.uid()`와 `anon`·`authenticated` 역할에 기대는데 **순수 postgres 컨테이너엔
  그게 없다.** 스텁을 만들어 넣으면 ⑤가 돌긴 하나 「진짜 Supabase에서도 같은가」가 미검증으로 남는다 —
  (라)를 고르면 **그 잔여 위험을 무엇으로 덮는지 함께** 낸다(예: 적용 후 실프로젝트에서 ⑤만 유호님이 1회 재확인).

넷 중 아무것도 못 고르면 **그것이 반려다**(§7 ④) — 그때 유호님께 올라간다.

### 3-3. 기록 6종 (L0 §8 — 하나라도 빠지면 미완)

적용 커밋·마이그레이션 버전 / Supabase 프로젝트와 **개발·운영 구분** / 실행 전 상태 / 실행 결과 /
적용 후 테이블·제약·RLS 검증 결과 / 실패 시 롤백·전진 수정 경로.

## 4. 완료 기준 — 테스트로 판정한다

1. 확인 쿼리 `판정` 칸이 **`✅ 전부 통과`**(기대 `6·6·5·0·3`).
2. `tests/L0스키마.test.js` 8건 초록 + **실행 층 검증 5종을 회귀로 남긴 것** 초록.
3. 계약 c4와 DDL 값목록이 **파생 관계**로 묶여 있다 — 계약을 고치면 테스트가 빨개진다.
4. 원격 CI 초록(로컬 초록은 CI 초록이 아니다).

## 5. 경계 — 이 발주에서 하지 않는 것

- **운영 프로젝트 적용** — 개발용 하나만. 운영은 별도 발주.
- **Edge Function 실물**(payload Zod 검증 · L0 §7-6) · **로그인 코드 발급 도구** — 기준선이 선 뒤.
- **`Settings → API → Exposed schemas` 변경** — `engine`은 노출하지 않는다(L0 §4-3).
- **계약 값·필드 뜻 변경** — 의미 층은 클로드 펜이다. 문제가 보이면 고치지 말고 반려.
- **DB 비밀번호·`service_role` 키를 대화·repo·로그에 남기기** — 어떤 형태로도.

## 6. 적용 주체 — ✅ 유호님 확정 **A** (2026-08-06)

**A. 유호님이 실행한다.** Supabase SQL Editor에 붙여넣고 `Run`, 확인 쿼리 `판정` 칸만 확인한다.
**AI는 어떤 자격증명도 갖지 않는다.** 이 확정이 §3-1 ⑤⑥⑦을 만든다.

**B(AI 원격 실행)는 기각이 아니라 보류**다 — 유호님 2026-08-06 「원격 관련은 차차」. 전제인 **개발 전용
자격증명 분리**가 그 자체로 발주 1건이라, 이 발주가 끝난 뒤 따로 판단한다.
🔴 **이 발주 안에서 B를 전제한 설계·배선을 미리 하지 않는다** — 안 쓸지도 모르는 자동화 경로가 남으면
「어느 쪽으로 적용됐는지」가 흐려진다.

유호님 손이 드는 지점은 이 발주 전체에서 **2회**다: ①이 발주를 Codex에 넘긴다 ②SQL을 붙여넣고 Run.
(「클릭 1회」 프레임은 2026-08-06 폐기됐다 — 인수·검증·기록이 그 사이에 있다.)

## 7. 반려 사유 (Codex → 클로드)

발주 검수 4문(분업 §4)에 하나라도 걸리면 구현 전에 반려한다:
①입출력이 구체적인가 ②빈 값·중복·네트워크 실패가 정의됐는가 ③완료 기준을 테스트로 판정할 수 있는가
④**구현 불가능하거나 모순된 요구가 없는가**(§3-1 ③ 「유호님께 CLI를 요구하지 않는다」와 ⑤ 「붙여넣기 1개」가
여기 걸린다면 그것도 반려다 — 대안을 제시하고 클로드가 판정한다. 단 **적용 주체 A 자체는 유호님 확정이라
반려 대상이 아니다** — 바꾸려면 클로드를 거쳐 유호님께 올린다).

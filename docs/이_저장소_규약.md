# SYNK-talk 저장소 규약

이 파일은 앱 고유 규약의 진입로다. 역할·소통·자율 실행·검증·최신 상태 확인은 [공통 원칙 연결](공용지침.md)이 가리키는 현재 원문을 따른다.

## 0. 제품과 현재 구현

SYNK-talk는 몽골어 화자를 위한 한국어 회화·교정 앱이자 SYNK의 학생 접점이다. Expo(앱)와 Supabase(DB·인증·서버 함수)를 사용한다. 제품 범위·역할 화면·교육 흐름은 [P0 제품 계약](P0_제품계약.md)과 관련 최신 결정을 읽는다. 범용 학원관리 SaaS를 새 목표로 잡지 않는다. Apps Script와 맞물린 변경은 실제 연결 계약을 확인해 두 저장소 범위를 조율한다.

현재 코드의 진입로는 [README](../README.md)다. 오래된 설계의 「없음·대기·완료」 표기를 현재 상태로 단정하지 않고 실행 코드·최근 변경·배포 증거를 대조한다.

## 1. 작업 진입과 기존 도구

각 모델은 `AGENTS.md`·`CLAUDE.md`·`GEMINI.md`에서 같은 공통 원칙과 이 문서로 들어온다. 문서를 모델별로 복제하거나 버전을 고정하지 않는다. 새 강제 훅·중앙 큐를 기본으로 설치하지 않는다.

기존 `.githooks/`에는 커밋 검사·커밋 정보·배포 알림이 있다. 설정은 `git config --get core.hooksPath`로 확인하며, 빈 설정만 보고 복원하지 않는다. `tools/install-hooks.js`는 이 기존 구성을 명시적으로 연결할 때 쓰는 선택 도구다. 실제 권한·인증 절차와 자격증명 보호를 우회하지 않는다.

## 2. 작업본과 자격증명

- 자격증명은 Git 밖에 둔다. `.env`·키 파일은 `.gitignore`로 제외하며 코드에 키를 박지 않는다. `.env.example`에는 이름과 비밀이 아닌 예시만 둔다.
- 편집 전 `git status`와 관련 diff를 읽는다. 다른 담당의 미커밋·스테이징을 보존하고 자기 경로만 지정해 커밋한다. `git add -A`·`git commit -a`로 공동 작업 전체를 담지 않는다.
- 테스트용 학생 자료는 합성한다. 비밀번호·토큰·학생 식별 데이터는 로그·결과물·모델 인계에 넣지 않는다.

## 3. 병렬 작업 범위

독립 코드 작업은 별도 worktree(작업 사본)로 나누고 공동 파일 소유 범위를 조율한다. `supabase/migrations/`는 상류 스키마이므로 한 담당이 통합한다. 서버 함수 `supabase/functions/`, 앱 `app/`·`src/`, 콘텐츠 `prompts/`·`contents/`는 의존 관계와 공유 계약을 확인해 병렬화한다. 배포·스토어 제출의 통합 책임은 하나다.

## 4. 데이터와 계약

- **학생 원본 음성을 보존한다.** 음성 전사는 발음 오류를 바꿀 수 있으므로 원본을 전사·교정으로 대체하지 않는다. 보관·철회는 현행 동의와 데이터 계약을 함께 따른다.
- 동의 범위는 [동의 문구](동의_문구_v1.md), 저장·불변·철회·인증은 [L0 데이터 계약](L0_데이터계약.md), 앱과 서버 통로는 [C0 API 계약](C0_API계약.md)을 읽는다. 옛 동의 버전을 이 문서에 복사하지 않는다.
- 필드·값목록은 `계약/수집_교정_계약.json`, 물리 변경은 `supabase/migrations/`와 연결된 시험을 대조한다. 제품·동의·데이터 의미 변경을 단순 지침 정리로 취급하지 않는다.

## 5. 디자인과 학생 접점

기능과 디자인을 함께 완성한다. 눈에 보이는 작업은 `synk-design`, 학생 접점 문안은 `synk-brand`를 먼저 사용한다.

값과 승인 자산은 appsscript의 현재 `DESIGN.md` → `docs/디자인_토큰.json`·브랜드 폰트 정본·`tools/lib/마스코트자산.js`에서 가져온다. `docs/명품_기준_v1.md`의 관련 항목과 최신 승인 실물을 함께 읽는다. 예전 킷 이름·색·서체·마스코트 파일을 이 규약에 다시 고정하지 않는다.

앱의 번역·소비 위치는 `src/테마.js`·`src/기호.js`·`src/소리.js`·`assets/`다. 원문을 갱신한 것과 앱·빌드에 반영한 것은 구분한다. 앱의 모드, 아이콘, 사운드, 실패음 금지 등 기존 승인 조건도 `DESIGN.md` 관련 절에서 확인하고 보존한다. 목록·애니메이션은 현재 화면의 상한·실측을 근거로 고른다. 과거 「전환 대상 0」 판정을 새 화면의 영구 금지로 사용하지 않는다.

## 6. 외부 스킬과 검증

설치된 스킬은 이번 작업에 필요한 내용만 읽고 제품·데이터 계약과 맞춘다. Supabase 작업에서는 보안·권한을 포함해 관련 공식 지침을 참고할 수 있다. 과거 특정 범주를 읽지 말라는 규칙으로 실제 인증·데이터 보호를 누락하지 않는다.

관련 시험은 `node --test tests/<관련 파일>`, 전체는 `npm test`다. 테스트 목록·구현·실기기·배포를 각각 확인하며 로컬 통과를 운영 완료로 보고하지 않는다. 기능 완성·계약 검토·배포의 역할은 [개발 분업](개발_분업.md)에서 연결한다.

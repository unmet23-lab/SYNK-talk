# SYNK-talk 저장소 규약

> 이 파일 = **이 저장소 고유 규칙**의 정본.
> 공용 규칙(역할·소통·판정·검증)은 `docs/공용지침.md` — 그쪽은 **생성물**이라 손으로 고치지 않는다.
> 고칠 일이 생기면 SYNK-appsscript의 `CLAUDE.md`(정본)를 `/evolve`로 고치고 다시 내보낸다.

## 0. 이 저장소는 무엇인가

**몽골어 화자를 위한 한국어 비동기 회화·교정 앱**(회화 앱 v0). 스택 = Expo(앱) + Supabase(DB·인증·함수).

- 학원 운영(출석·급여·수납·리포트카드)은 **여기 없다.** 그건 SYNK-appsscript가 계속한다 — 건드리지 않는다.
- 이 저장소의 승부처는 화면이 아니라 **교정 품질**이다. 화면은 그다음이다 — 단 화면을 만들 때의 기준은 §5(디자인은 기능과 사실상 동급).
- 🚫 **범용 학원관리 SaaS는 설계 목표가 아니다**(멀티테넌시 금지). 대상은 B2C 학생.

## 1. 여러 AI 도구가 들어온다 — 그래서 가드가 git 층에 있다

Claude Code · Codex · Kimi · OpenCode가 이 저장소에서 돈다.

- 프로즈 지침은 도구마다 진입점이 다르다: `CLAUDE.md`(Claude Code) · `AGENTS.md`(Codex·Kimi·OpenCode). **둘 다 얇은 포인터일 뿐** 내용은 `docs/`에 하나로 있다.
- 하네스 훅·스킬·메모리는 **도구별로 다르거나 아예 없다.**
- 그래서 **기계 강제는 git 층에만 둔다** — `.githooks/pre-commit`은 어느 도구가 커밋하든 걸린다.

**clone 후 반드시 1회**: `node tools/install-hooks.js` (안 하면 가드가 아예 안 돈다)

## 2. 절대 규칙 3가지

1. **자격증명은 git 밖.** `.gitignore`가 지킨다. 「추가하지 않기」로는 안 지켜진다 — 실사고 4건.
2. **커밋은 범위를 못 박는다**: `git commit -m "..." -- 경로들`. `git add -A`·`commit -a` 금지 — 세션이 여럿인데 인덱스는 저장소당 하나다.
3. **키는 코드에 박지 않는다.** `.env`에 두고 `process.env`로 읽는다. `.env.example`에 **이름만** 커밋한다.

## 3. 레인(병렬 작업) 규약

worktree/Orca로 병렬 작업할 때 레인은 **파일이 아니라 층**으로 가른다.

| 레인 | 대상 | 제약 |
|---|---|---|
| 스키마 | `supabase/migrations/` | **항상 1개만** — 모든 층의 상류 |
| 서버 로직 | `supabase/functions/` | 병렬 |
| 앱 화면 | `app/`, `src/` | 병렬 |
| 콘텐츠·교정 프롬프트 | `prompts/`, `contents/` | 병렬 |

- 배포·스토어 제출은 **통합 레인 하나**에서만.
- 다른 레인이 만지는 층은 건드리지 않는다. 조율했으면 커밋 메시지에 한 줄 남긴다.

## 4. 데이터 원칙 (되돌릴 수 없는 것들)

- 🔴 **학생 원본 음성은 반드시 보관한다.** STT는 학생의 발음 오류를 「고쳐서」 전사하는데, **그 오류가 정확히 우리가 모으려는 데이터다.** 전사는 다시 돌릴 수 있지만 원본은 소급 불가.
- 학생 데이터는 동의 v18.7 범위 안에서만. 남의 학원 데이터는 범위 밖.
- 개인정보가 든 실데이터를 저장소에 커밋하지 않는다(픽스처는 합성).

## 5. 디자인 — 유호님 확정 (2026-08-05)

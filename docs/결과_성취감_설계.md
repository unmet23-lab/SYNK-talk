# 숙제 결과 성취감 — 결과를 보는 순간의 설계

> **v1.0 · 2026-08-13** — 유호 지시 08-13: 「숙제 결과 같은 걸 볼 때, 수행을 열심히 하거나 잘 한 학생이 성취감·만족감을 자연스럽게 느낄 수 있게 시스템을 구성해 달라.」
> 판정 정본은 문서가 아니라 코드다 — `lib/꼬리.js`(줄 판정·문구)와 `tests/꼬리.test.js`(불변식)가 정본이고, 이 문서는 **지도와 이유**만 진다(같은 판정을 두 곳에 적으면 갈라진다).
> 시제: 미개원(학생 0명). 이 문서의 「학생이 느낀다」는 설계 의도이지 실측이 아니다.

## 0. 한 문장

**성취감은 칭찬·점수·배지로 만들지 않는다 — 그 학생 자신의 궤적에서 «어떤 참인 사실을 골라 보여줄 것인가»로 만든다.** 잘 한 날은 성과의 사실이, 열심히만 한 날은 노력의 사실이 서고, 결론은 시스템이 아니라 학생이 스스로 잇는다(스스로 이은 결론이 가장 자연스러운 성취감이다).

이 원칙은 새로 세운 것이 아니라 이미 서 있던 것이다: 철학 Ⅱ-8 「점수가 아니라 대조」 · ㉢ 비교는 어제의 그 학생과만 · 꼬리 규격(숫자 0 · 「잘했어요」류 평가어 0 · 남 비교 0 — 재료의 성질로 강제).

## 1. 결과 순간 지도 — 어디가 이미 서 있고, 어디가 비었었나

학생이 「숙제 결과」를 만나는 순간은 다섯이다. 축은 유호 지시의 둘: **잘 함**(성과)과 **열심히 함**(노력).

| 순간 | 성과 축 | 노력 축 |
|---|---|---|
| ① 제출 직후 (말하기 완료카드) | — (교정 전이라 성과 데이터가 아직 없다) | ✅ 시도 수 · 「스스로 다시 도전」 · 「어제보다 N개 더 냈어요」 |
| ② **답장 = 결과의 본체** (교정 카드) | ✅ 꼬리 3종 — 단 **무오류일 때만** | 🔴 **0 이었다** ← 이번에 채운 자리 |
| ③ 어제의 나 (S1-11) | ✅ 교정 재발화 고리 한 줄 | ✅ 낸 것·다시 말한 것 표 + 늘어난 칸 잉크 100% |
| ④ 서클 종이 (다음 날 아침) | ✅ 잘 된 문장(kept — 1순위가 「지난번에 틀렸다가 이번에 맞은 자리」) · trend_line | ✅ 제출 자체가 kept ④순위(「끝까지 낸 것 자체」) |
| ⑤ 시즌 회고 | 사람이 판정(자동화 대상 아님 — 철학 ①의 「목표」 주석) | 〃 |

**진단**: 오류가 남은 교정 — 언어 학습자의 **대부분의 날** — 의 답장은 교정문·코랄 태그·몽골어 해설뿐이었다. 열심히 한 학생이 결과의 본체(②)에서 받는 온기가 0. 꼬리는 「없는 성공을 말하지 않는다」가 옳아서 무오류에만 섰는데, 그 옳음이 노력 축까지 침묵시키고 있었다.

## 2. 채운 것 — 꼬리 2종 (커밋 한 벌 · 새 화면 0 · 새 사건 0 · 새 저장 0 · 계약 개정 0)

재료는 서버가 이미 가진 한 칸이다: `learning_events.retry_of_event_id` — 「교정 후 다시 낸 고리」, 이 시스템의 **유일한 결과 변수**(L0 §9-2 · `functions/progress` 의 교정재발화와 같은 물리).

- **`재발화무오류`** — 전에 고쳐 준 문장을 다시 말했고, 이번 교정이 무오류: 「전에 고쳐 준 문장을 다시 말했는데, 오늘은 고칠 데가 없었어요.」 **교정이 먹힌 순간이 학생 눈앞에서 닫힌다** — 시스템 전체에서 가장 축하할 사건인데 그동안 잦던자리·이어서로 뭉개져 있었다. 인과(「다시 말해서 맞았다」)는 재지 않았으므로 쓰지 않는다 — 두 사실을 병치하고 잇는 것은 학생이다.
- **`재발화`** — 되말하고 냈는데 오류가 남은 날: 「전에 고쳐 준 문장을 다시 말하고 냈어요.」 성공을 한 글자도 주장하지 않는 **노력 사실 줄** — 「없는 성공 금지」와 축이 달라 충돌하지 않는다. 벽지 방지는 기존 연속 금지 기계가 그대로 진다(오류·재발화가 이어지면 한 번 내고 멈춘다 — 회귀로 못박음).

우선순위 `첫무오류 > 재발화무오류 > 잦던자리 > 이어서 > 재발화` — 성과 줄이 서는 날은 성과가 먼저고, 노력 줄은 성과 줄이 못 서는 날의 몫이다.

**앱 변경 0줄.** 답장 화면은 `growth_note` 를 이미 그대로 그린다 — 서버가 짓는다는 유호 확정(08-12)의 배당이 여기서 났다. 배선: `functions/corrections` 이력 조회에 bool 한 칸 추가뿐.

**④와의 공명**: 밤에 「재발화무오류」 꼬리를 읽은 학생은 다음 날 아침 서클 종이의 「잘 된 문장」 칸(kept 1순위 = 같은 사실)에서 그 순간을 조원 앞에서 말로 한 번 더 지나간다 — 같은 성취가 두 자리에서, 새 수집 0으로.

## 3. 철학 게이트 (학생 대면 — ①②③④ 전부)

| 층 | 판정 | 근거 |
|---|:--:|---|
| ①재미·도움·신선 | ✓ | 재미=「시스템이 나를 봤다」의 재미(자극 아님) · 도움=꼬리가 가리키는 곳이 자기 오류 궤적이라 다음 행동(오늘 ② 슬롯)과 직결 · 신선=존재 판정 + 연속 금지라 늘 참인 벽지가 안 된다 |
| ②엔진 | 소비 | S1-11 과 같은 축(P0 §5 — 「뇌를 먹이는 행위 자체가 보상 표시」). 수집 신설 0 — 되말기·응답 동기가 오르면 S1-3 라벨이 늘 «수 있으나» 미측정이라 근거로 안 쓴다 |
| ③운영 | ✓ | 전자동(서버 순수 함수) · 사람 손 0 |
| ④완결 | ✓✓— | 모였나 ✓(재료는 이미 쌓이는 `retry_of_event_id`) · 닿았나 ✓(조회 사슬 기존) · 늘었나 — 해당 없음(소비 방향 — 대장 칸을 채우는 기능이 아니다) |

㉢ 대조: 남·평균·등수는 **입력에 들어오지도 않는다**(꼬리한줄 인자 회귀가 못박음). ㉡: 사람 손 0. ㉣: 반출 0.

## 4. 스스로 반박해 접은 것 (재제안 방지)

| 안 | 접은 이유 |
|---|---|
| `attempt_no`(여러 번 말하고 냄) 꼬리 | 같은 사실을 완료카드가 그날 밤 이미 말한다(「스스로 다시 도전했어요」) — 이틀에 걸쳐 두 번 말하면 인정이 아니라 인플레다 |
| 답장 화면에 effort 전용 칸·배지·면 | 「성취를 상자에 담으면 배지가 되고, 배지는 점수의 다른 이름」(답장화면 꼬리 스타일 주석 — 이미 내려진 판정) |
| 연속 제출 스트릭 줄 | 서클 폐기안 「완료 현황판·스트릭」과 같은 계열 + 끊긴 날 기죽임이 설계에 내장됨 + 문턱(며칠부터?)을 못 잰다(학생 0명) |
| 결과 화면 소리·햅틱 | achieve 는 발송 자리 전용(게임층 §3-1) · 읽는 화면의 절제 원칙 — 아래 도전안으로만 남긴다 |
| 앱단에서 줄 생성 | 기기에 이력을 안 쌓는 앱이라 재료가 없다 — 유호 확정 08-12 「서버에서 짓자」 그대로 |
| 어제의 나 확장(증감 말·줄었을 때 문구) | 「줄었다고는 말하지 않는다」가 이미 판정돼 서 있다(`lib/견줌.js`) |

**예약 1**: 유령 캐릭터의 결과 반응(맑기·빛이 꼬리 순간에 응답)은 캐릭터 v4 판정(⏳유호 — 획득 조건·배치)에 물려 있다 — 그 트랙이 열리면 이 꼬리 종류가 트리거 재료가 된다. 여기서 짓지 않는다(앱 캐릭터 0줄 유지).

## 도전안 1 (라벨 분리 — 본체 아님 · ⏳유호)

**`재발화무오류` 한 종류에만 achieve 효과음 1회**: 소리 킷·게이트가 이미 있어 코드 몇 줄이고, 이 사건은 시스템에서 가장 드문 성취라 「효과음=흔한 보상」 인플레가 없다. 접은 이유(읽는 화면 절제)와 정면 충돌이라 본체에서 뺐다 — 유호님 판정감.

## 5. 배포 상태 (정직 고지)

- 코드·회귀 커밋 = 라이브 아님. **`corrections` Edge Fn 재배포가 남는다**(응답 필드 확장 아님 — 내부 조회 한 칸이라 앱 신구 어느 조합에도 안전).
- 몽골어판 꼬리: 기존 규칙 그대로 — 검수자가 문구를 확인하기 전까지 `lang: 'ko'` 뿐(지어내지 않는다).

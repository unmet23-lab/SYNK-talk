## §0 검수자에게 — 무엇을 봐달라는 것인가

**"좋은 설계네요"는 필요 없다.** 이미 12번 이상의 설계 왕복과 반박 패스를 거쳤고, 아래 §9에 우리가 기각한 것과 그 근거를 전부 적어 뒀다. 같은 제안을 다시 받으면 시간만 쓴다.

우리가 원하는 것은 **이 설계가 조용히 실패할 지점**이다. 구체적으로 세 가지:

1. **소급 불가 누락** — 지금 안 만들면 1~2년 뒤 데이터를 통째로 못 쓰게 되는 필드·라벨·동의 조항이 아직 남아 있는가. (§6 스키마 + §10 질문 1)
2. **산수가 틀린 곳** — 검수 인력 1명, 학생 90명 전제의 용량 계산(§7)이 성립하는가. 여기가 틀리면 파일럿 2주차에 파이프라인이 막힌다.
3. **엔진 관점의 오설계** — 모은 데이터가 실제로 파인튜닝/RAG에 투입 가능한 형태인가. 라벨 축이 잘못 잡혀서 "많이 모았는데 못 쓰는" 결과가 되는 지점.

**전제**: 우리는 아직 한 줄도 구현하지 않았다. 지금이 스키마를 바꾸는 데 비용이 가장 싼 시점이고, 파일럿이 시작되면 소급 불가 영역이 생긴다.

## §3 왜 이 데이터인가 (해자의 논리)

초기 엔진 학습 데이터는 **빅테크가 가질 수 없는 것**이어야 한다. 그렇지 않으면 범용 모델이 좋아지는 순간 우리 자산이 0이 된다.

### 우리가 내린 판정 3개

**(1) 모을 것은 몽골어가 아니라 「몽골 사람이 발음한 한국어」다.**
몽골어 자체의 음성·번역 문제는 구글·OpenAI가 언젠가 푼다. 하지만 **"몽골 억양이 섞인, 문법이 틀린 한국어"**는 시장이 작아서 아무도 안 푼다. 이게 우리가 독점 가능한 유일한 지점이다.

**(2) 값은 「모델을 학습시킬 양」이 아니라 「어디서 무너지는지의 지도」다.**
150명 × 2년 ≈ 3만 건 규모로는 범용 LLM의 한국어 능력을 바꾸지 못한다. 이 데이터가 들어갈 자리는 **모델 가중치가 아니라 진단·교정 로직(파인튜닝된 어댑터 + RAG + 규칙)**이다.
→ 따라서 **많이가 아니라 유형별로 고르게** 모아야 한다. 200명이 같은 조사 실수만 반복하면 3만 건이어도 유형 30개짜리다.

**(3) 반자동(사람이 최종 확정하는) 데이터가 100% 자동 데이터보다 값지다.**
`(입력, 모델 1차안, 사람 최종본)` 3원쌍은 돈으로 살 수 없는 supervised 데이터다. 이 diff 자체가 파인튜닝 쌍이자 선호쌍(preference pair)이 된다.
→ 그래서 **AI 1차안을 영구 보존**한다(§6 테이블 2). 사람 최종본만 남기면 이 자산이 사라진다.

## §4 게임화 설계 — 「데이터 수집 = 숙제 = 미니게임」

### 4-1. 핵심 등식
이 셋은 **한 물건**이다. 별도의 "데이터 수집 활동"을 만들지 않는다. 학생이 숙제를 하면 그게 미니게임이고, 미니게임을 하면 그게 곧 학습 데이터다.

**모든 기능의 1차 설계 게이트 3축** — 하나라도 안 닿으면 만들지 않는다 *(⚠이 문구는 AND 로도 읽혀 갈림을 낳았다 — 판정 방식은 2026-08-10 유호 확정 = **OR**: 「셋 중 어디에도 안 닿으면 만들지 않는다」 · P0 §9-B B-3 종결)*:
1. 회사 엔진(개인 학습용 AI 챗봇) 학습에 도움이 되는가
2. 개인별 학습 성향·심리 성향을 파악할 수 있는가
3. TOPIK 취득에 도움이 되는가

### 4-2. 미니게임 필수 규칙 3
| # | 규칙 | 이유 |
|---|---|---|
| ① | 게임에 **TOPIK 문법을 활용**한다 | 재미가 학습을 대체하면 학원이 아니라 오락이 된다 |
| ② | 수강생 심리·행동 특성을 **암묵적으로** 수집한다 | 설문으로 물으면 답이 왜곡되고, 물어야 하는 순간 자동화가 깨진다 |
| ③ | **99% 자동화** 가능해야 한다 | §1의 제약 — 손일은 6개월 안에 죽는다 |

### 4-3. 수집 항목의 두 층
원안은 20행 표로 설계되어 있다(원장 작성).

- **100% 자동 10행** — 학생이 앱을 쓰기만 하면 사람 개입 0으로 쌓이는 것. 타이핑 지연, 백스페이스 횟수, 문항별 체류 시간, 접속 패턴, 정답률, 힌트 클릭 등.
- **반자동 10행** — AI가 1차안을 만들고 사람이 확정하는 것. 발화 전사·교정, 오류 유형 라벨, 몽골어 해설, 쓰기 첨삭 등. **여기가 해자다.**

일반 텔레메트리(자동층)는 그 자체로는 흔한 데이터다. 값은 **반자동 10 + 몽골 특화 자동 3**(키릴 혼입 탐지 / 모음 원순성 / 코드스위칭)에 있고, 자동층은 반자동층과 **조합될 때만** 의미를 갖는다.

### 4-4. 게임화 메커니즘 (앱에서 학생이 실제로 보는 것)

**(a) 1분 마이크로 챌린지** — 학습의 기본 단위
교과서적 상황("철수야 안녕")이 아니라 **유학 실전 시나리오**로 만든다:
- "교수님 멘탈 구하기" (과제 늦었을 때 메일 쓰기)
- "보고서 교정" (어색한 문장 고치기)
- "알바 변명" (지각했을 때 사장님께 말하기)
- 비자 연장 / 원룸 계약 / 병원 증상 설명 / 출입국 서류 부족 상황

**(b) 말하기 과제 = 20~30초**
길게 잡으면 학생이 안 하고, 검수 용량이 터진다(§7). 20~30초는 두 제약의 교집합이다.

**(c) 트랙 2종을 쌍으로**
- **낭독(shadowing)** — 표준 문장을 듣고 따라 읽기 → 발음·억양 측정용
- **자유 발화** — 상황만 주고 알아서 말하기 → 문법·어휘 오류 측정용
둘을 섞으면 어느 쪽 신호인지 구분이 안 되므로 **과제 유형 태그를 필수로** 붙인다.

**(d) 어조 전환 과제 (style shift)**
같은 내용을 대상 3인에게 다르게 말하게 한다:
① 친구에게(반말) ② 처음 본 동년배에게(해요체) ③ 교수님/사장님께(합쇼체)
→ 몽골 학습자가 가장 어려워하는 높임법 데이터가 **1:1 대응쌍**으로 쌓인다.

**(e) 재시도 루프**
교정을 받고 **다시 제출**할 수 있게 한다. 이 고리(`retry_of_homework_id`)가 설계 전체에서 **유일한 결과 변수**다 — "무엇이 이 학생을 실제로 바꿨는가"를 재는 값.
→ ⚠ 현재는 선택 사항이다. **기본 루프로 강제할지 검토 중**(§10 질문 4).

**(f) 정의적 여과막 낮추기**
10대는 사람 앞에서 틀리는 것을 극도로 부끄러워한다. AI 상대로는 마음껏 틀린다. 이게 앱이 교실보다 발화량을 늘릴 수 있는 유일한 근거이고, 게임화의 진짜 목적이다.

### 4-5. 게임화에서 **일부러 뺀 것**
- 🚫 **포인트·현금 할인 보상** — 인플레와 편법 제출을 부른다. (별도 판정으로 기각)
- 🚫 **리그·랭킹 상시 노출** — 하위권 이탈을 가속한다.
- 🚫 **난이도 자동 하향** — 도달제 승급과 충돌하고, 인과가 역전된다(못해서 쉬워지면 영원히 안 는다). 강사 알림까지만.
- 🚫 **소음 환경 하드모드** — 소음은 나중에 합성으로 만들 수 있다. 수집 항목이 아니다.

## §5 파이프라인 (제출 → 학습셋)

```
[Expo 앱] 학생이 20~30초 녹음 제출
    ↓ (WAV 16kHz/16bit · 음성처리 off)
[Supabase] Storage(비공개 버킷) + DB row (status='pending')
    ↓ n8n Schedule 폴링 1~2분
[n8n] signed URL로 오디오 취득
    → Whisper STT (verbose_json — 세그먼트별 타임스탬프 + 신뢰도)
    → Gemini flash (유료 티어) : 교정문 + 오류 유형 + 몽골어 해설 초안
    ↓
[Supabase] ai_processing_logs 에 1차안 + 모델/프롬프트 버전 기록 · status='ai_processed'
    ↓
[검수 대시보드 — Expo 앱 안의 검수자 화면 / PC는 Expo web]
    검수자가 오디오를 듣고 키보드 원클릭으로 승인 or 수정
    ↓
[Supabase] verified_learning_datasets · status='verified'
    ↓
파인튜닝 / RAG 적재
```

### 설계 결정 4개와 그 이유
1. **트리거는 웹훅이 아니라 폴링(1~2분)** — 웹훅만 쓰면 유실 시 pending 행이 고아가 되고 재시도 경로가 없다. 폴링은 자가치유된다.
2. **오디오 파생 지표(발화 속도·정적)는 서버에서만 계산** — 앱에서도 계산하면 두 값이 갈라졌을 때 어느 쪽이 진실인지 영영 모른다.
3. **폐기는 소프트 삭제만**(`status='discarded'`, 파일 존치) — 노이즈 데이터도 강건성 학습 재료다.
4. **검수자는 청취 전 승인 불가** — Enter 키를 막고 `listened_ms`를 저장한다. 검수자 1명 체제에서 이것이 유일한 품질 계기판이다.

## §6 스키마 전문 (PostgreSQL — 그대로 실행 가능한 상태)

> 정본은 `docs/발주_수집파이프라인.md` §1. 아래는 검수용 스냅샷이다.
> `[CHK-n]`은 구현 착수 시 실물과 대조할 미확정 지점 표시다.

```sql
-- 1) 학생 제출 과제
create table student_homeworks (
  id uuid primary key default gen_random_uuid(),
  student_id uuid not null,               -- FK: 기존 learners 테이블 [CHK-1]
  homework_type varchar(50) not null,     -- 'audio' | 'text' | 'essay_image'
  task_type varchar(20) not null,         -- 'read_aloud'|'response'|'free'|'interview'|'style_shift'|'exam_review'
  challenge_id varchar(50),               -- 마이크로 챌린지 식별

  -- ↓ 「그때만 알 수 있는 값」 4종 (나중에 못 붙인다)
  level_snapshot text,                    -- 제출 시점 급수. 급수가 오르면 과거 값은 재구성 불능
  addressee_level varchar(10),            -- 'banmal'|'haeyo'|'hapsyo' — style_shift 전용
  target_phonemes text[],                 -- 이 과제가 겨냥한 음소('ㅃ','ㅡ','ㅢ','받침ㄹ'…)
  retry_of_homework_id uuid references student_homeworks(id) on delete set null,

  prompt_seed text,                       -- 매회 무작위 문장(대리 제출·재사용 오염 방어)
  file_url text,
  duration_sec numeric(6,2),
  privacy_class varchar(20) not null default 'voice_high',
  self_reported_tension smallint,         -- 1~5, 모의면접 직후 1문항

  telemetry jsonb,                        -- 예:
  -- {"first_key_delay_ms":420, "backspace_typos":3, "chunk_insert_count":0,
  --  "hints":[{"t_ms":1200,"type":"word|structure|mn_explain","stuck_ms":3400,"recovered":true}],
  --  "item_dwell_ms":{"q7":41200}}
  -- 측정 안 된 키는 0이 아니라 생략한다(0 디폴트는 「측정 없음」과 「실측 0」을 영영 못 가른다)
  -- chunk_insert_count>0 = 타자 지표 신뢰 하락(추천단어 탭·글라이드 입력은 자모가 안 남는다)

  speech_wpm numeric(5,2),                -- 파생 캐시(원천=stt_segments, 재계산 가능)
  pause_duration_sec numeric(5,2),
  status varchar(20) not null default 'pending',  -- pending|processing|ai_processed|verified|discarded
  retry_count integer not null default 0,
  is_audit_sample boolean not null default (random() < 0.05),  -- 무작위 5% 감사 레인
  created_at timestamptz not null default now()
);

-- 2) AI 1차 처리 로그 (1차안 영구 보존 — verified 와의 diff 가 파인튜닝 쌍)
create table ai_processing_logs (
  id uuid primary key default gen_random_uuid(),
  homework_id uuid not null references student_homeworks(id) on delete cascade,
  stt_model_version text not null,        -- 'whisper-1'
  llm_model_version text not null,        -- 'gemini-flash-3.6'
  prompt_version text not null,           -- 'correct-v1'
  stt_raw_text text,
  stt_segments jsonb,                     -- [{start,end,text,avg_logprob,no_speech_prob}]
  stt_avg_logprob numeric(6,3),           -- 낮을수록 저신뢰 → 검수 우선순위
  ai_corrected_text text,
  detected_error_types text[],            -- 복수 라벨 [CHK-2]
  l1_source_phrase_draft text,            -- 직역 오류의 원인이 된 몽골어 관용구(AI 추정)
  mongolian_explanation_draft text,
  processed_at timestamptz not null default now()
);

-- 3) 검수 완료 학습셋 (금고 — 연쇄삭제 금지)
create table verified_learning_datasets (
  id uuid primary key default gen_random_uuid(),
  homework_id uuid not null references student_homeworks(id) on delete restrict,
  ai_log_id uuid not null references ai_processing_logs(id) on delete restrict,
  verified_student_text text not null,    -- 「들린 대로」 — 학생 오류 보존(파인튜닝 입력)
  verified_corrected_text text not null,  -- 교정문(파인튜닝 출력)
  final_mongolian_explanation text,
  error_types text[] not null default '{}',
  l1_source_phrase text,                  -- 확인된 원인 몽골어 관용구
  code_switch_spans jsonb,                -- [{start_ms,end_ms,mn_text}] 몽골어 혼입·추임새(За·Тийм)
  rubric_scores jsonb,                    -- 쓰기 과제: {"내용":12,"전개":8,"어휘문법":9,"감점":[...],"예상등급":"4급"}
  was_edited boolean not null,            -- false=무편집 승인 / true=수정 승인(고가치 표본)
  listened_ms integer not null default 0, -- 검수자 실제 청취 시간
  inspector_id uuid not null,
  verified_at timestamptz not null default now()
);

-- 4) 접속 0도 기록 (부재는 이벤트가 아니다 — 안 한 날은 행이 없으면 관측 자체가 없다)
create table daily_activity (
  student_id uuid not null,
  activity_date date not null,
  session_count integer not null default 0,
  primary key (student_id, activity_date)
);
-- pg_cron 으로 매일 1회, 재적 전원에 대해 upsert(활동 없으면 0)

create index on student_homeworks (status, created_at);
create index on student_homeworks (student_id, created_at);
create index on ai_processing_logs (homework_id);
create index on verified_learning_datasets (homework_id);

alter table student_homeworks enable row level security;
alter table ai_processing_logs enable row level security;
alter table verified_learning_datasets enable row level security;
alter table daily_activity enable row level security;
-- 정책 의도: 학생=자기 행 insert/select 만 · 검수자 role=전체 select + verified insert · n8n=service_role
-- Storage: homework 버킷 비공개(미성년 음성) · 접근은 signed URL 만 · 파일 삭제 정책 없음(폐기=소프트)
```

### 학생 프로필 쪽 추가 3문항 (가입 시 1회 · 학생 화면 비노출)
| 필드 | 값 | 용도 |
|---|---|---|
| `home_aimag` | 성장한 아이막(몽골 행정구역) | 지역별 억양 편차. "수도 vs 지방" 이분법은 예측력이 없어 실제 지역명으로 받는다 |
| `gender` | — | **화자 편향을 재는 유일한 축.** 학습 라벨이 아니라 분포 점검 전용 |
| `goal_track` | study(유학) / work(EPS·취업) / culture(K컬처) | 같은 오류도 목적에 따라 처방이 다르다. 보호자 목적과 본인 목적이 갈리면 **본인 것**을 적는다 |

### 스키마 설계에서 의도적으로 내린 결정 6개
1. **최종 텍스트가 2칸인 이유** — Whisper는 오발음을 표준어로 「고쳐 듣는다」. 한 칸만 두면 파인튜닝의 **입력 쪽(학생의 실제 오류)이 소실**된다. 그래서 「들린 대로」와 「교정문」을 분리했다.
2. **3테이블을 하나로 병합하지 않은 이유** — 단일 테이블 + JSONB 병합안을 검토했으나 기각했다. ①verified 두 텍스트의 NOT NULL 강제가 불가능해 금고에 빈 값이 조용히 들어간다 ②모델 업그레이드 후 재처리하면 1차안 이력이 덮인다 ③추출기가 JSONB 키 오타에 무방비.
3. **verified 의 FK는 CASCADE 가 아니라 RESTRICT** — 숙제 한 건을 지웠을 때 학습셋이 연쇄 삭제되면 금고 사고다.
4. **`was_edited`를 따로 두는 이유** — 무편집 승인과 수정 승인은 값이 다르다. **수정된 표본이 금**이다.
5. **모델·프롬프트 버전 3필드** — 없으면 드리프트 위에 학습하게 된다.
6. **`is_audit_sample` 무작위 5%** — 저신뢰 샘플링만으로는 **「AI가 자신 있게 틀린 것」**을 영원히 못 잡는다.

## §7 검수 용량 산수 (가장 깨지기 쉬운 지점)

검수자는 **1명**을 전제한다(개원 초 인건비 제약).

| 항목 | 값 |
|---|---|
| 재원 학생 | 90명 (개원 초 가정) |
| 말하기 과제 | 1인 1일 20~30초 |
| 하루 총 오디오 | 90 × 25초 ≈ **37분** |
| 비원어민 + 코드스위칭 전사·검수 계수 | 오디오 1분당 **4~6분** |
| 전량 검수 시 | 2.5 ~ 3.7시간/일 → **1명 초과** |
| 실제 운영 | 저신뢰 구간 우선 + 무작위 5% 감사 → **약 1시간/일** |

**따라서 전량 검수는 하지 않는다.** AI 1차안을 그대로 승인하는 비율이 높아야 성립하고, 그 비율이 낮으면(=AI 품질이 나쁘면) 즉시 파이프라인이 막힌다.

⚠ 우리가 아는 위험: 초기 3개월은 Gemini 프롬프트가 안정화되지 않아 수정률이 높을 수 있다. 그 구간의 대책이 아직 없다 → **§10 질문 2**.

참고로 원장이 직접 해야 하는 검수(해설 작성 등)를 전량 넣으면 주 22~45시간이 나온다. 이건 명백히 불가능하므로 **상한 설계**를 별도로 두기로 했다.

## §8 소급 불가 항목 (지금 안 하면 1년치가 죽는 것)

이 6개는 "싸지만 지금 안 하면 되돌릴 수 없다"는 기준으로 골랐다.

| # | 항목 | 안 하면 벌어지는 일 |
|---|---|---|
| ① | 녹음을 **PCM WAV 16kHz/16bit + 음성처리 off**로 저장 | 압축·자동 게인이 목소리 떨림·미세 발음을 지운다. 연 저장량 ~67GB는 감당 가능 |
| ② | 모의면접 직후 **긴장도 자기보고 1문항**(1–5) | 긴장 음성 데이터에 라벨이 없으면 영원히 해석 불가 |
| ③ | **과제 유형 태그**(낭독/응답/자유/면접/어조전환) | 뒤섞이면 발음 신호와 문법 신호를 분리할 수 없다 |
| ④ | **접속 0인 날도 행 생성**(일일 배치) | 부재는 이벤트가 아니다 — 행이 없으면 "안 했다"와 "관측 안 됨"이 같은 모양이 된다 |
| ⑤ | 가입 폼 3문항(아이막·성별·목적) | 나중에 물으면 전원에게 다시 물어야 한다 |
| ⑥ | **동의 6항목 개정** | 아래 참조 — 이게 최대 게이트다 |

### 동의 6항목 (법적 게이트 · 수집 개시 전제)
음성 · 얼굴 영상 · 교실 녹음(제3자 목소리) · **국외 이전** · 제3자 처리 위탁 · **철회 시 기학습분 유지**

> 몽골 개인정보보호법(2021-12-17 제정 / 2022-05-01 시행)은 **음성을 생체정보로 명시**한다. 목적란에 "AI 모델 개선·학습"이 없으면 2~3년치 데이터가 통째로 막힌다.
> 학생 상당수가 미성년이고, 문구는 **몽골어 병기 + 원어민 검수**가 필요하다.
> ⛔ **이 개정 전에 수집한 데이터는 엔진에 못 쓴다.** 파일럿 시작의 하드 게이트다.

## §9 이미 기각한 것과 그 근거 (재제안 불요)

검수자가 시간을 낭비하지 않도록 전부 적는다. **새로운 반증이 있으면 환영하지만, 아래 근거를 넘지 못하는 재제안은 받지 않는다.**

| 기각한 제안 | 근거 |
|---|---|
| 몽골어 음성 자체를 수집 | 목적은 한국어 회화 교정이다. 필요한 건 「몽골 억양이 섞인 한국어」이지 「자연스러운 몽골어」가 아니다 |
| 소음 환경 다양화 수집 | 소음은 **사후 합성 가능**하다. 수집 항목이 아니라 경험(연습 모드) 백로그 |
| 조음 위치 3D 시각화(혀·입술 추적) | **단안 카메라에는 기준자가 없어** 절대 길이(mm)가 나오지 않는다. 입술로는 평음/격음/경음 구분(VOT)이 보이지도 않는다. 원순 모음 3쌍만 서버측 처리로 축소 |
| 음소 단위 Forced Alignment 지금 도입 | 원본 WAV를 무손실 보존하므로 **언제든 소급 가능**. 지금 붙이면 파이프라인만 무거워진다 |
| 손글씨 OCR로 학습 데이터 수집 | OCR의 언어모델이 학생 오타를 정타로 **「복원」**해 버린다 — 신호 파괴자. 손글씨는 연습용, 데이터는 타이핑으로 |
| 학생 오답률 기반 함정문제 **자동** 생성 | 문항당 응답 30건 미만에서는 노이즈와 신호를 구분할 수 없다. 강사 승인을 거치는 반자동으로 강등 |
| 난이도 자동 하향 | 인과 역전(못하면 쉬워져서 영영 안 는다) + 도달제 승급과 충돌. 강사 알림까지만 |
| 자판 전환(키릴↔한글) 이벤트 추적 | React Native가 IME 전환을 보지 못한다. controlled TextInput은 한글 조합을 깨뜨린다. **키릴 혼입 탐지 + 덩어리 삽입 플래그**로 축소 |
| 세션 리포트·TTS 3단계 속도·상대 랭킹·신조어 DB·비자 RAG·B2B 데이터셋 | 전부 **수집이 아니라 앱 기능/콘텐츠**다. 필요한 원천은 이미 위 스키마에서 파생된다 |
| 포인트·현금 보상으로 제출률 유도 | 편법 제출과 포인트 인플레를 부른다 |
| 실시간 음성 대화(S2S)를 지금 붙이기 | 1단계 범위 밖. 배치 STT와 아키텍처가 다르고, 평가 층을 나중에 교체하려면 분리해야 한다 |

## §10 우리가 답을 못 낸 질문 (검수자에게 묻는 것)

**Q1. 소급 불가 누락이 더 있는가?**
§8의 6개 + §6의 「그때만 알 수 있는 값」 4개로 충분한가. 파일럿 시작 후에는 못 만드는데 우리가 못 본 것이 있다면 그것이 이 검수의 최대 가치다.

**Q2. 초기 3개월 「AI 수정률이 높은 구간」의 대책이 없다.**
§7의 1시간/일은 AI 1차안 품질이 안정된 뒤의 숫자다. 초기에 수정률이 높으면 검수자 1명이 막힌다. 프롬프트 안정화 전까지의 현실적 운영안은?

**Q3. 라벨 축(오류 유형)을 어떻게 잡아야 나중에 안 갈라지는가?**
현재 오류 유형 enum을 기존 계약의 「레코드 5형」에서 파생시키기로 했고, 여기에 `politeness`(문화적 무례·과도한 직설)와 `mishearing`(적다/작다류 음향 착오) 2축 추가를 검토 중이다. 파인튜닝·RAG 양쪽에서 쓰이려면 이 축이 어떤 형태여야 하는가?

**Q4. 재제출을 「기본 루프」로 강제해야 하는가?**
현 설계에서 **결과 변수는 `retry_of_homework_id` 하나뿐**이다. 나머지는 전부 입력·성향 데이터라, 개인화 엔진이 상관관계는 배워도 "무엇이 실제로 이 학생을 바꿨는가"(처방)를 못 배울 위험이 있다.
→ 한 번 내고 끝이 아니라 **내고·피드백 받고·다시 내야 완료**로 만들면 모든 숙제가 `(before, feedback, after)` 3원쌍이 된다. 비용은 학생 손 1회 추가.
이 강제가 정당한가, 아니면 이탈률을 감당 못 하는가?

**Q5. 18개월 압축이 데이터 관점에서 성립하는가?**
원래 24개월 계획을 18개월로 줄였다. 파일럿 10~20명 → 개원 후 90~117명 규모에서, 18개월 시점에 "개인 맞춤 회화 챗봇"을 낼 만한 검수 쌍이 쌓이는가. 쌓인다면 최소 몇 쌍이 필요한가. 안 쌓인다면 무엇을 먼저 포기해야 하는가.

**Q6. 파인튜닝 방식 판정이 아직 없다.**
현재 "파인튜닝 / RAG 적재"라고만 적혀 있고 어느 쪽인지 안 정했다. 우리 데이터 규모(1~2년에 수천~수만 쌍)에서 **전체 파인튜닝 / LoRA 어댑터 / 선호학습(DPO) / RAG + 규칙** 중 무엇이 맞는가.
참고로 우리 스키마는 이미 선호쌍을 만들 수 있다: `verified_student_text`(프롬프트) + `ai_corrected_text`(rejected) + `verified_corrected_text`(chosen), 필터는 `was_edited = true`.

**Q7. 이 설계에서 「조용히 실패할」 지점은 어디인가?**
크래시나 에러가 아니라, **아무 일도 안 일어나는 것처럼 보이면서 데이터가 죽는** 형태의 실패. 우리가 이미 4번 겪은 유형이라 특히 겁내고 있다.

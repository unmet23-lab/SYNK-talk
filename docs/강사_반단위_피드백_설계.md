## 2. 판정 ① — 「피드백」은 골든 큐가 아니다 (두 큐를 가른다)

`955e8a16` 은 「큐를 반으로 쪼개면 칸마다 물량이 줄어…」라고 적었는데, **어느 큐인지가 안 정해져
있었다.** 정하면 이렇게 갈린다:

| | 골든 판정 큐 (N10·N11 · 이미 있음) | **피드백 큐 (이 설계가 신설)** |
|---|---|---|
| 목적 | 엔진 채점 — AI 교정이 맞나 | 학생에게 갈 교육적 피드백 |
| 모집단 | 지난 주 AI 교정 행 **전체** | **내 반** 학생의 이번 주 제출 |
| 뽑는 법 | 주간 시드 무작위 5건 | 반 안 전건(내림 뒤 남은 것) |
| 반 축 | ❌ **넣지 않는다** | ✅ 1차 축 |

🔴 **골든 큐에 반 축을 넣으면 안 되는 이유**: M2 §4 가 「무작위가 이 회로의 심장」이라 적은 것은
장식이 아니다 — N12 성적표의 분모가 그 무작위성 위에 선다(`M2 §5` 「분모는 무작위 층만」). 반으로
층화하면 강사마다 다른 5건을 보게 되고, 그 순간 model·prompt_ver 승률은 **모델 성능이 아니라 반
구성**을 잰다. 유호님이 요청한 것은 「피드백을 쉽게」이지 「채점 표본을 반별로」가 아니므로 이 분리는
지시를 좁히는 것이 아니다.

- 🔑 **둘이 서로를 돕는 관계는 그대로 산다**(`955e8a16` 원문의 뜻): 자동 하강이 「맞음」을 걷어내
  피드백 큐가 「적지만 전부 볼 값어치」가 된다. 다만 그 도움은 **같은 큐여서가 아니라 같은 술어를
  써서** 생긴다.
- 강사 탭 = 메뉴 **둘**(피드백 · 골든 판정). 골든은 주 5건이라 「이번 주 끝」이 뜨는 화면이고,
  피드백은 반이 1차 축인 화면이다. 🚫 둘을 한 화면에 합치기 — 합치면 주 5건 상한이 반 큐의
  물량에 묻혀 「유인이 0인 업무」(M2 §4)가 영영 안 끝난다.

## 3. 판정 ② — 반의 원본 자리 (선행 배관 · 화면보다 먼저)

**표 둘 + 칸 하나.** 시트가 이미 표라서 원본도 표여야 1:1 이고, 강사 축은 칸 하나로 못 선다
(한 반 여러 강사가 실측이다 — §1 ⓐ).

```
engine.classes        class_key text primary key   -- ' 평일11A' 6자 · 시트 A열 그대로 (영원히 안 바뀌는 키)
                      display_name text            -- 표시명(E열) · 학생·학부모가 보는 이름
                      seats int, weekday_kind text, start_time text
                      active boolean not null default true
engine.staff_classes  (staff_id, class_key)        -- 복합 PK · 공동 담당이 정상
engine.learners       class_key text references engine.classes  -- null 허용 = 미배정
```

- 🔑 **키를 `평일11A` 로 그대로 쓴다 · uuid 를 새로 발급하지 않는다.** 시트가 정본이고 그 키는
  「영원히 안 바뀐다」가 유호 확정이다. uuid 를 끼우면 두 저장소가 키를 대조할 방법이 사라지고,
  대조 못 하는 다리는 어긋난 날 증상이 「조용함」뿐이다.
- 🔑 **`display_name` 을 원본에 같이 둔다** — 표시명은 「시즌 1 이후 각 반이 직접 짓는다」라
  바뀌는 값이다. 앱이 키를 그리면 학생이 `평일11A` 를 보게 된다.
- 🔴 **다리는 확장이지 신설이 아니다** — `roster-ingest` 가 그 문이다. 단 지금은
  `on conflict (student_code) do nothing` 이라 **넣기만 하고 갱신을 안 한다**. 반은 바뀌는 값이라
  (반배정은 사람 확인 단계다 · 함수 머리말 :5) **`do update set class_key = excluded.class_key`**
  가 필요하다. ⚠ 갱신 대상을 `class_key` **하나로 한정**한다 — 전체 upsert 로 넓히면 이름·연락처가
  시트 오타 한 번에 원본에서 덮인다.
- 🔑 **규칙은 한 벌** — 반 칸 검증(빈 값 · 시트에 없는 반)은 `lib/명부규칙.js` 에 넣는다. CLI 와
  스윕이 그 하나를 공유하는 것이 F269 의 처방이다(문이 둘이어도 규칙은 한 벌).
- **배정 이력 표는 안 만든다.** 학생이 반을 옮기면 옛 제출도 새 반 큐로 따라간다 — 피드백은
  「지금 그 학생을 가르치는 강사」가 하는 것이라 그게 맞는 동작이다. 이력이 필요한 소비자
  (누가 가르쳤나 집계)는 **지금 0**이고, 「나중에 쓸 수 있는 모양」은 통과가 아니다(철학 ④).
  ⚠ 되돌릴 때 비싼 판정이므로 §8 에 판정 자리로 남긴다.

## 4. 판정 ③ — 화면 (Glide 판을 승계한다 · 새 발명 0)

1. **첫 화면 = 내 반 카드 그리드**(§1 ⓑ 승계). 카드 한 장 = 반 하나, 카드에 **그 반의 지금** 한 줄:
   `👥 N명 · ✍️ 피드백 대기 K건`. 🔑 대기 건수가 카드에 있어야 강사가 **들어가기 전에** 어디부터
   볼지 정한다 — Glide 판에서 보스 HP 가 하던 일과 같은 자리다.
2. **반을 열면 = 그 반의 피드백 큐**(학생별 카드). 카드 = 학생 이름 + 제출 한 줄 + AI 교정 프리필.
3. 🚫 **반 화면에 학생 간 비교를 두지 않는다**(철학 ㉢ — 등수·평균·「다른 아이보다」 금지).
   반 카드의 `N명`·`K건`은 **반의 상태**이지 학생 서열이 아니다. 학생 카드는 정렬만 하고 순위를
   안 매긴다(정렬 키 = 오래된 것 먼저 — 「밀린 것」이 위로 오는 것이지 「못하는 아이」가 위로 오는 게 아니다).
4. 🚫 **강사에게 전교생 큐를 기본값으로 보이지 않는다**(`955e8a16` 🚫 승계). 담당 반이 0개인
   강사는 빈 화면이 아니라 「배정된 반이 없습니다」를 본다 — 빈 화면과 권한 없음이 같은 모양이면 안 된다.

## 5. 판정 ④ — G2 「맞음」 자동 하강이 서는 자리 (㉡ 의 나머지 한 벌)

**실측이 `955e8a16` 의 전제를 반쯤 뒤집었다.** 그 세션은 「검수 큐는 제출 전건 무조건 적재 →
지금은 「맞음」도 사람이 읽는다」까지는 맞게 봤는데, **그 앞에 AI 교정이 한 번 도는 것을 안 셌다**:

- `functions/correct/index.ts:146` 대기조건에 **task 필터가 0**이다 — `body_original` 이 비어 있지만
  않으면 무엇이든 벤더에 간다. G2 짚음 갈래는 `submission.created`+숙제제출+`body_original`(문장 전문)이라
  **그대로 걸린다**.
- `engine.review_queue` 의 AI 조인은 **inner** 다(`join lateral (… actor_kind='ai') ai on true`) —
  즉 **AI 교정 행이 없으면 애초에 큐에 안 뜬다.**

🔴 **그래서 조회 시점 하강은 늦다.** 늦게 내리면 두 가지가 이미 벌어져 있다:

1. **과교정률 계기판이 거짓으로 부푼다** — 정답대로 고친 문장을 AI 에게 「고쳐 달라」고 보내면 AI 는
   무언가를 만들어 낸다. 그 행은 골든 표본 풀(= 지난 주 AI 교정 행)에 들고, 뽑히면 강사가
   「①원문이 이미 맞다 = 과교정」을 누른다. M2 §5 가 「21/21≠100% 실패모드를 상시 감시하는 숫자」로
   세운 계기판이 **G2 정답 문장 때문에** 나빠진 것처럼 보인다. 조회 시점 하강은 이걸 못 막는다.
2. **벤더 호출이 그만큼 돈이다**(`vendor-api-billing` — 캐싱+배치로 월 ~2,400원 · cron 하루 3회).

✅ **처방 = 술어를 `correct` 의 `대기조건()` 에 건다. 한 곳뿐이다.**

- 술어 = 「G2 제출이고 `task_snapshot` 의 정답과 제출 문장이 같다」 — **파생이라 저장 0**
  (`955e8a16` 의 「`is_correct` 안 만듦」 제약 그대로 지킨다).
- **새 표 0 · 새 열 0 · 새 상태값 0** — AI 행이 안 생기면 inner 조인이 알아서 큐에서 뺀다.

🔴 **여기서 진짜 함정 = 판정이 두 벌이 되는 것.** 판정 정본은 순수 함수
`lib/보고서교정.판정(선택자리, 교정문, 정답)` 인데 `대기조건()` 은 SQL 조각이다. SQL 에 손으로
다시 적으면 **그게 두 번째 정본**이고, 갈리는 날 증상은 「어떤 맞음은 걸러지고 어떤 맞음은 안
걸러진다」라 아무 데도 안 남는다.

✅ **저장소에 이미 이 문제의 처방이 있다 — 그걸 쓴다(새 패턴 0).** `lib/동의게이트.지금유효술어` ·
`lib/골든표본.풀술어` 가 선례다: **SQL 술어 «텍스트»를 lib 이 내보내고** 두 소비자가 그 하나를
끼운다(`골든표본.js:37` 원문 — 「둘이 각자 적으면 그게 두 번째 정본이고, 갈리는 날 분모와 분자가
다른 풀을 센다」).

- `lib/보고서교정.js` 가 `맞음술어`(SQL 텍스트)를 `판정()` **옆에** 내보낸다.
- 재현 가능한 이유 = **정규화가 정확히 셋뿐**이라서다(`:106` §6-4 ② — 앞뒤 공백 제거 · 연속 공백
  1칸 · 종결 마침표 유무 무시). 그 셋은 SQL 에서 짧게 선다. ⚠ **정규화가 넷째를 얻는 날 술어도
  같이 오른다** — 회귀가 그 결속을 진다(픽스처 한 벌을 `판정()` 과 SQL 양쪽에 먹여 답이 같은지).
- 🚫 술어를 「대충 느슨하게」 적기 — 느슨하면 **안 고친 답까지 AI 를 건너뛰어** 진짜 오류가 아무에게도
  안 간다. 새는 방향이 「통과」인 자리라 좁게 연다(모르면 AI 로 보낸다 = 안전 방향).
- 🔑 **`대기조건()` 이 함수인 것이 여기서 값을 한다** — 그 조각은 「대기 수」와 「집는 목록」 **두
  질의에 같이** 끼워진다(함수 머리말 :140 「대기 12인데 집히는 건 0」을 막으려고 그렇게 뒀다).
  한 곳에 걸면 계기판과 실동작이 같이 움직인다. 🚫 목록 쪽에만 걸기.
- 🔴 **`pipeline_jobs.status` 를 새 값으로 옮기지 않는다** — 옮기려면 CHECK 개정(마이그)이 필요한데,
  얻는 것은 「대기 N」의 정확도뿐이고 그건 위 술어가 이미 준다.

**학생 쪽 ㉡ 서버 판정은 `955e8a16` 안 그대로 선다**(재판정 없음): `POST /v1/events` 응답이
이미 `{ok, results:[…]}` 사건별 배열이라 **칸 하나만 더한다 · 새 엔드포인트 0**. 피드백은
**앉음(3문장) 밖**에서만 — 안에서 주면 2·3번의 `selected_option`·`latency_ms` 가 탐지 능력이
아니라 방금 받은 힌트에 대한 반응이 된다(재는 층이 값을 바꾼다).

**한 수 더**(유호 08-12 채택 · 미착수): 대조 문항의 **자리를 매일 결정적 셔플**(`prompt_seed` 기반 ·
무작위 ✗ — 재현 가능해야 한다). 3장 중 대조가 늘 같은 자리면 학생이 자리를 외워 §9-③ 계기판이 거짓이 된다.

## 6. 착수 순서 (앞이 안 서면 뒤가 못 선다)

1. **반 원본 + 다리** — 마이그(표 2 + 칸 1) · `명부규칙` 반 검증 · `roster-ingest` 좁은 upsert · 회귀.
   ⚠ 이것만으로는 화면이 아무것도 안 바뀐다. **그래도 먼저다** — 뒤 셋이 전부 이 조인 위에 선다.
2. **G2 「맞음」 술어**(`lib/보고서교정.맞음술어` → `correct` 대기조건) — 1번과 독립이라 **병행 가능**.
   회귀 셋 = 「정답과 같은 G2 제출은 안 집힌다」 + 「정답과 다른 G2 제출은 집힌다」 +
   「발화녹음은 영향 0」. ➕ 결속 회귀 = 같은 픽스처를 `판정()` 과 SQL 술어에 먹여 답이 갈리면 적색.
3. **`teach` 피드백 경로 둘** — `GET /v1/teach/feedback/classes`(내 반 + 대기 건수) ·
   `GET /v1/teach/feedback/queue?class_key=`. 경로표에 등재하면 메서드·안내문이 파생된다(:131).
4. **화면** — 반 카드 그리드 + 반 큐(§4).
5. **리허설 실왕복** — 인수 조건 = 담당 반 밖 학생이 **0행**으로 막히는 것을 일부러 심어 증명한다
   (「내 반만 보인다」를 화면 규약으로 두면 서버가 안 지킨다).

## 7. 「똑똑하게」 4층 게이트 (철학 Ⅰ-3 · 배관이라 ③④를 진다)

- ③ **운영** — 반 배정은 이미 사람이 하는 확정 하나(크루카드 접수→반배정)이고, 이 설계는 그 손을
  **안 늘린다**. 늘어나는 손 = 0. 「맞음」 자동 하강은 사람 손을 **줄인다**(㉡ 정면 복무).
- ④ **완결 3칸** — 모였나 **✓**(반은 시트에 이미 있다) · 닿았나 **✗→○**(다리가 이 설계의 1번) ·
  늘었나 **✗** 🔴 **정직하게 적는다**: 이 설계가 이해 대장의 새 칸을 채우지는 않는다. 채우는 것은
  G2 자체(㉡ 사람 이해)이고, 이 문서는 **그 재료가 사람 손에 막히지 않게 하는 배관**이다.
  ⚠ 그래서 이 설계 단독으로 「엔진이 자랐다」고 보고하지 않는다.

## 8. 혼자 정하지 않는 것 (유호님 판정 자리 · 답 없이도 1·2번은 선다)

1. **강사 계정이 실재하나** — `engine.staff` 에 `teacher` 행이 지금 0인지, 개원 때 몇 명인지.
   0이면 4번 화면은 **볼 사람이 0명**이라 리허설까지가 상한이다.
2. **반 배정 이력**(§3 마지막) — 「학생이 반을 옮기면 옛 제출도 새 반으로 따라간다」로 뒀다.
   되돌리려면 표 하나가 더 생기므로 지금 아니면 비싸진다.
3. **운영 배포** — 라이브라 유호님 승인 자리(리허설까지가 세션 몫 · M2 §8 선례).

### 2-1. 학생 — 하루 1회, 90초 〔S1〕

**세 호흡, 한 흐름**(`말하기_설계 §6` 정본 · 화면 전환 없음):

| 호흡 | 무엇 | 남는 것 (`task_type` / `task_format`) |
|---|---|---|
| **① 듣기** | 어제 내 발화에 온 AI 답장을 듣는다 | 재생 완료율(§5 S1-1) |
| **② 따라 말하기** | 답장 속 핵심 문장 1개를 신호음 뒤에 따라 말한다 → **교정이 나간 다음 날엔 「내 교정문」이 이 자리에 온다** | `submission.created` · **`발화녹음` / `낭독`** · `mission_id`·목표 음소·hesitation_ms·재시도 전부 |
| **③ 답하기** | 내 말로 답한다 (급수 1~2는 **골라서 답하기** — 선택지 2개를 소리로) | `submission.created` · **`발화녹음` / `자유발화`** — 또는 `choice.selected`(필드 전량 = c6 선택로그 묶음) |

🔴 **`task_type`(어느 통로)과 `task_format`(무슨 형식)은 다른 축이다** — ②③이 같은 통로로 들어오되 형식이 달라야 섀도잉과 자유발화가 갈린다. 한 칸에 담으면 나중에 못 가르고, **낭독 데이터로 회화 모델을 학습시키는 사고가 조용히 성립한다.**

이후: 제출 직후 **자기 목소리를 한 번 듣는다** → 어제 교정이 와 있으면 본다 → 결과는 **어제의 나와 비교**로 보인다(랭킹 아님).

▶ `submission.created` ×2 · `session.abandoned` · `choice.selected` · `correction.viewed` · `correction.responded`(학생의 채택/무시/수정 · `retry_of_event_id`)

- 🔴 **②와 ③은 쌍이라서 값이 있다** — 같은 학생·같은 날·같은 주제의 **통제 발화 + 자유 발화**. 어느 한쪽만 모으는 공개 데이터셋은 있어도 쌍은 없다. **하나만 구현하면 그 기간은 영영 반쪽이다.**
- 🔴 `choice.selected`의 **표시 순서·추천 여부**를 안 남기면 「학생의 선호」와 「우리가 밀어준 것」이 영원히 구분되지 않는다.
- 🔴 **「제출 안 함」이 분모로 존재해야 한다** — `task.assigned`가 없으면 「안 온 날」과 「낼 게 없던 날」이 같은 모양이 된다.

## 3. 완료 조건 — 「끝」의 정의

### 3-1. S1 완료 조건

**A. 관통 확인** — 전부 ✅여야 S1 종료. `✅승인`=유호님 확정분 6개 · `⏳`=v3에서 늘어난 것(§9-B).

1. `✅승인` **실기기 2대(iOS/Android)**에서 학생 계정으로 로그인해 세 호흡 제출이 된다(에뮬레이터 아님).
2. `✅승인` 원본 음성이 **Storage 규칙 경로**(`{voice|image}/{learner_id}/{uuid}.{ext}`)에 올라가고, **파일 헤더에서 잰 값**이 `capture_meta.server`에, 앱이 요청한 설정이 `capture_meta.app`에 **매 건** 기록된다.
   - 정본 포맷 = **PCM WAV 16kHz / 16bit / mono · 기기 음성처리(AGC·노이즈 억제·에코) off**.
   - 🔴 **Expo 기본 녹음으로는 이 포맷이 안 나온다**(`HIGH_QUALITY` = `.m4a`·44.1kHz·2채널 · Android 옵션 목록에 PCM/WAV 없음). **커스텀 네이티브 녹음기 또는 후처리가 S1의 필수 작업이다** — 소급 불가 배선 ①이라 「나중에」가 없다(§10-A-2).
   - 🔑 **규격 밖이어도 업로드를 거부하지 않는다** — 거부하면 학생의 발화가 영영 사라진다. 대신 **규격 밖이면 경고를 남긴다**(그 경고가 실제로 남는지까지 확인한다).
   - 🔴 **1회 실측이 아니라 매 건 기록이다**(`C0 §4-2`) — 앱 업데이트로 AGC가 조용히 켜지면 증상 없이 그 뒤 전량이 오염된다. 확인 불가 값은 `unknown`.
3. `✅승인` `POST /v1/events`가 c6 필드를 받는다. **필수 집합의 판정 근거 = F0의 이벤트별 Zod 스키마** — 그게 서기 전에는 이 항목을 판정할 수 없다(§10-①).
4. `⏳` **②와 ③이 같은 세션에서 쌍으로 저장된다**(`correlation_id`로 묶이고 `task_format`이 서로 다르다).
5. `✅승인` 사람이 확정한 교정이 원 제출에 **고리로 묶여** 학생 화면에 돌아온다(`correction.viewed` → `retry_of_event_id`). 확정 통로는 §7-2.
6. `✅승인` `task.assigned`가 매일 배치로 채워지고, 접속 0인 날이 **분모와 함께** 남는다.
7. `✅승인` **오프라인 5건 축적 후 복귀 시 전건 저장**되고 각 `occurred_at`이 수신 시각으로 덮이지 않는다.
   판정은 화면 동작이 아니라 **저장된 행 수**로 한다(`C0 §7`).
8. `⏳` **엔진을 꺼도 학생이 제출할 수 있다** — 강등 경로가 실제로 동작하고 `degraded=true`가 행에 남는다(§6-4).
9. `⏳` **배치를 1회 강제 실패시키면 알림이 뜬다**(§6-5) — 큐가 비는 것은 강등으로 안 잡힌다.

| **S1-8** | **교정 열람·응답** | `correction.viewed` → `correction.responded`(채택/무시/수정 · `retry_of_event_id`) | ③(라벨)·② | **3년차** 교정 수용 라벨(N5) · **「학습이 일어났다」의 유일한 직접 신호** | ㉠㉡㉢ | 교정이 없으면 화면에 안 뜸 |
| **S1-9** | **오늘의 말 배달**(§6) | `intervention.delivered` · `output_text` · `model` · `prompt_ver` · `cited_refs`(자리) · **`degraded`** | ④(AI 게이트웨이) | **1년차부터** 벤더·프롬프트 교체 근거(N12) · A-5 회수의 전제 | ㉠ | 강등 = 큐/고정 과제 · `degraded=true` |
| **S1-10** | **과제 배정**(분모) | `task.assigned` · 접속 0 행 일일 배치 | ②(참여) | **2년차** 이탈 예측의 분모 — 없으면 「안 온 날」과 「낼 게 없던 날」이 같은 모양 | ㉡ | 배치는 엔진과 무관하게 돈다 |
| **S1-11** | **어제의 나와 비교** | **S1에서는 조회 전용 — 사건 없음.** 열람 기록이 필요하면 c7 개정(§10-⑧) | ②(소비) | 화폐 교체의 대체 훅 — **뇌를 먹이는 행위 자체가 보상 표시**(N8 축) | ㉡ | 전날 값으로 표시 |

🔑 **S1-3 ↔ S1-11이 한 데이터의 양면이다** — 교정문 재발화는 **수집으로는** 3점 종단 라벨이고, **학생에게는** 「어제의 나와 비교」 화면의 재료다. 지표를 위해 따로 만든 화면이 아니라, 수집이 그대로 동기 부여가 된다.

⚠ **S1에 넣지 않은 것과 이유** — 기준은 「소비냐 아니냐」가 아니라 **「그 입력이 S1에 존재하냐」**다(S1-11도 소비지만 전날 값 하나로 서므로 들어온다):
어휘 산출 원장(N7)·조 편성 저장(N9) = 입력원이 S1 밖(교재 연동·수업 운영) · 승급 게이지(N13) = 급수 도달 이력이 아직 0 · 오류 지문 히트맵(N14) = 태그 해소 이력이 아직 0.

⚠ **AI 기능의 강등 정본은 §6-4다.** 이 표의 마지막 열은 S1 동작에 대한 사본이고, 교정 1차안·전사(STT)처럼 S1 동작이 아닌 AI 기능은 §6-4에만 있다. **개정할 때는 §6-4를 고친다.**

## 6. 「하루 한 문장」 배달 경로 — 설계 (S1-a)

### 6-1. 무엇을 만드나

**학생마다 하루 1건, 전날 밤에 미리 만들어 큐에 넣는다.** 앱은 큐에서 읽기만 한다.

```
전날 밤 배치 ─┬─ 첫날      → 고정 도입 과제(§4-5)
              ├─ 교정 있음 → ②슬롯 = 어제 그 학생의 교정문(조회 1건)
              └─ 그 밖     → 급수·목적으로 다음 문장 1개 생성(AI 호출 1회)
                                    │
                                    ├─▶ task.assigned  (배정 = 분모 · S1-10)
                                    └─▶ intervention.delivered (AI가 한 말 · S1-9)
                                                    │
                          앱: 오늘 내 것 1건 읽기 ──┘   (앱에서 엔진 호출 0)
```

🔴 **큐의 실체 = 새 테이블이 아니다.** `task.assigned` 사건 + 그 `task_snapshot`이 곧 큐다. 앱은 「오늘 날짜의 내 `task.assigned` 1건」을 읽는다.
> ✅ **읽는 자리도 섰다**(2026-08-07 · `functions/tasks` = `C0 §4-3 ①` · 리허설 실왕복 **37/37**). 배치가 쓴 `event_id`·문장·`intervention_id`를 앱이 **그대로** 받는 것을 같은 실행에서 대조한다. 남은 것은 ①AI 갈래 ②`pg_cron` 등록 ③운영 배포.
> ✅ **구현 완료**(2026-08-07 · `functions/deliver` + `lib/오늘과제.js` · 리허설 실왕복 23/23 · 새 테이블 0).
> ① **`task_snapshot`은 payload가 아니라 `engine.submissions`에 싣는다** — 계약(`수집_교정_계약.json` 필드층)이 그 이름을 **「내용」층**에 두었고 그 층의 물리 자리가 거기다. payload로 옮기면 `C0 §4-1`의 허용 payload 목록 개정(=새 판)이 필요한데 **계약을 안 바꾸고 서는 길이 이미 있었다.** ⚠대가: 「제출 수」를 셀 때 반드시 `learning_events.event_type`으로 걸러야 한다 — `count(submissions)`로 세면 **배정이 제출로 세어진다**(왕복시험 ⑥이 그 자리를 지킨다).
> ② 멱등키 `task:{learner_id}:{YYYY-MM-DD}`·`intervention:{…}` — 재실행은 `duplicate`로 접힌다(실측: 2회 실행 후 행 그대로).
> ③ 날짜는 **몽골 달력**으로 끊는다(`Asia/Ulaanbaatar` · 오프셋 상수를 안 적는다). UTC로 끊으면 몽골 오전 8시까지가 「어제」라 아침에 앱을 연 학생이 어제 것을 받는다.
> ④ **행의 `task_format`은 비운다** — 배정 1건에 ②낭독 + ③자유발화 두 형식이 든다(§2-1). 형식은 **호흡마다** 적고, 제출 행이 각자 자기 형식을 갖는다.
> ✅ `actor_kind`는 **`ai`**다(§10-A-1 — `system`을 새로 만들지 않았다).
> 이 자리를 비워 두면 Codex가 테이블을 만든다 — **`발주_수집파이프라인`이 이미 그 사고를 한 번 겪었다**(새 3테이블이 전부 `submissions`·`corrections`의 재발명이라 전량 폐기 · F124).
> 제출 후 AI 1차 처리를 태우는 `pipeline_jobs`는 **다른 큐**다(그건 들어온 것을 처리, 이건 나갈 것을 적재).

🔴 **배치 실행 위치 = Supabase Edge Function + `pg_cron`.**
`코어엔진`이 게이트웨이 실행 위치를 "서버측만 — Edge Function(권장) 또는 **별도** Apps Script 프로젝트"로 두고 **현 AS 프로젝트의 doPost 확장을 금지**했다(상담AI 점유 + HtmlService 전역 노출 사고 이력). 접속 0 배치가 이미 `pg_cron`으로 돌 예정이라 같은 층에 둔다.
⚠ 시간 트리거가 이미 있다는 이유로 **현 AS 프로젝트에 얹지 않는다** — 가장 쉬운 자리가 금지된 자리다.

### 6-2. 왜 실시간 생성이 아니라 큐인가

1. **강등이 공짜로 된다** — 엔진이 죽어도 큐엔 어제 만든 문장이 있다. 실시간이면 엔진 무응답 = 화면 공백이고, 그건 `코어엔진 A-4`가 금지한 「내부 엔진이 전 앱의 단일 장애점」이다.
2. **첫 화면이 빠르다** — 학생이 앱을 여는 순간 생성 대기가 없다.
3. **비용이 예측된다** — 하루 학생 수만큼만 호출. 앱 사용량과 무관.
4. **`task.assigned`가 자연스럽게 생긴다** — 큐에 넣는 그 순간이 배정 시점이다(분모 · S1-10).

### 6-3. 문장을 무엇으로 고르나 (의미 계약 — 구현은 발주)

🔴 **S1에서 쓰는 입력은 둘뿐이다.** 개인화는 여기서 짓지 않는다.

| 입력 | 쓰임 |
|---|---|
| `level_snapshot`(급수) | 문장 길이 · ②생략 여부(`말하기_설계 §6 급수별 조정`) |
| `goal_snapshot`(유학/취업/K컬처) | 주제 선택 |

⛔ **오류태그 기반 재출제·간격 반복·복습 상한은 S1에 넣지 않는다** — 세 이유가 겹친다:
1. **`전수분석 §13-2` 재제안 금지 목록의 첫 항목이 「SRS/간격 반복 큐」**다(N14=현재 상태만·N7=측정만·학5=A1 게이트 안). 「일일 상한 N」은 우회가 아니라 스케줄러가 있다는 증거다.
2. **개인화는 E2다** — `코어엔진`이 학습자 모델의 첫 소비자를 "talk 첨삭·복습 추천"으로 두고 **E0는 계약 조항뿐·🚫선행 구축**이라 못박았다. 수집 0건 상태에서 소비 회로를 짓는 것이 그 금지의 정확한 형태다.
3. **S1에서 한 번도 안 돈다** — 오류태그는 사람 확정을 거쳐야 나오는데 S1엔 검수 화면이 없다(§7-2 CLI). 검증되지 않는 로직을 첫 발주에 넣으면 §4-1이 경계한 「막힌 것이 통과한 것처럼 보이는 상태」를 자기가 만든다.

> 🔴 **셋째 갈래(급수·목적으로 문장 1개 생성)는 아직 안 붙었다** — 모델·프롬프트 계약이 없다(어느 모델·어떤 프롬프트·비용은 이 문서가 정하지 않았다). **그 자리를 비워 두지 않는다**: §6-4 강등 경로가 그대로 받아 「전날 문장 → 없으면 고정 도입 과제」로 나가고, 그 배정은 **`degraded=true`로 행에 남는다.** 그래서 AI가 한 줄도 못 쓰는 지금 상태가 원장 화면에서 **강등 100%로 보인다** — 감추면 §4-1이 경계한 「막힌 것이 통과한 것처럼 보이는 상태」가 된다. 이 갈래를 붙이는 것이 **S1-a의 남은 일**이다.
> · 교정문 조회는 「지난 배정 **뒤에** 새로 확정된 것」만 쓴다 — 「최신 1건」으로 잡으면 같은 교정문이 매일 ②슬롯에 다시 온다.
> · 동의가 없는 학생은 **배정하지 않는다**(`consent_ver`가 not null). 우회로를 만들지 않고, 그 학생은 §6-5 미달로 드러난다.

🔴 **②슬롯 규칙은 예외로 S1에 든다**: 교정이 나간 다음 날 따라 말하기 목표 문장을 **학생 자신의 교정문**으로 바꾼다(S1-3 · `전수분석 N4` 확정분).
이것은 모델이 아니라 **직전 교정 1건을 그대로 가져오는 조회**다 — 무엇을 언제 복습할지 고르지 않으므로 SRS 게이트에 걸리지 않는다. 새 단계도 추가하지 않는다(90초 그대로).

### 6-4. 강등 경로 (`코어엔진 A-4`가 P0 기능표 열로 지정)

| AI 기능 | 엔진(서버) 무응답 시 기본 동작 |
|---|---|
| 오늘의 말 배달 | **큐의 전날 문장** → 그것도 없으면 **고정 도입 과제** |
| 교정 1차안 | 초안 없이 사람 확정 큐에만 올린다 — **제출은 절대 막지 않는다** |
| 전사(STT) | `transcript_state=pending`으로 두고 나중에 재실행 — 저장은 영향 없음 |

- **강등 사실을 행에 남긴다** — `degraded=true`(c6 필드) + 발생 시각. 이것이 N20(강등 배지·가용성 로그)의 데이터 실체이고, 원장 화면의 「강등 발생 건수」(§3-3) 재료다.
- 🔑 원칙: **엔진이 죽어도 수집은 계속된다.** 수집이 채점보다 우선이라는 `C0 §4-2` 원칙과 같은 축이다.

### 6-5. 🔴 배치가 **안 돈 것**을 감지한다

강등은 「엔진이 답을 못 했다」를 덮지만, **배치 자체가 죽으면 큐가 비고 그건 강등으로도 안 잡힌다.**
전원이 며칠 고정 과제로 돌아도 증상은 조용하고, 그걸 보는 눈은 원장 주 1회 화면뿐이다.

- **감지선**: 배치 시각 이후 그날 `task.assigned`가 **재적 학생 수보다 적으면** 알림.
- **채널·기한·수신자**(A-8 해소): 배치 예정 시각 **+30분**에 검사 → 미달이면 **원장 화면 상단 배너 + `intervention.delivered`가 아닌 운영 로그 1행**. S1 구간에는 수신자가 유호님 한 명이라 별도 발송 통로(메일·푸시)를 만들지 않는다 — **화면에 뜨는 것이 알림이다**(만들 것을 늘리지 않는다).
- **복구 기준**: 재실행 후 `task.assigned` 수가 재적 수와 같아지면 해소. 결정론적 멱등키라 **재실행이 안전하다**(§10-A-4).
- **완료 조건에 넣는다**: 배치를 1회 강제 실패시켰을 때 알림이 뜨는지 본다(§3-1 A-9).
- ⚠ 「조용한 미적용은 통과와 같은 모양」 — 이 저장소가 반복해서 겪은 형태다.
- ✅ **구현 완료**(2026-08-07) — `POST /functions/v1/deliver?점검` 이 재적·배정·강등을 세고 `미달`을 낸다. 실측으로 참을 봤다(동의 없는 학생 1명 때문에 미달=true). **남은 것 둘**: ①`pg_cron` 등록(배치 시각 + 그 30분 뒤 점검) ②원장 화면 배너 — 지금 미달은 **함수 로그와 응답에만** 뜬다.
- 🔴 **덫 하나를 발견해 막았다**(`tests/마이그레이션이름.test.js`): Edge Function 넷이 계약판을 `schema_migrations`의 **최신 이름**에서 `_c<숫자>.sql` 로 읽는다. 그래서 다음 마이그레이션을 `..._cron_deliver.sql` 처럼 판 없이 이름 지으면 **API 4개가 동시에 500** 이 된다 — 위 ①을 마이그레이션으로 넣을 때 정확히 밟을 자리였다.

## 7. 위임받은 판정 — ✅확정

### 7-1. 강사·검수자·원장 인증 (`L0 §4-5`가 P0로 승격 · ✅유호 확정 ④)

**현재 상태(실측)**: 검수 대시보드 발주는 **착수 차단** — `role='inspector'` 인증이 미설계인데 화면을 발주했고, `service_role` 키가 Expo 번들에 들어가면 **회수가 불가능**하다.

| 항목 | ✅확정 |
|---|---|
| 화면 | **Expo 앱 안 역할 화면**(기존 확정 유지) · PC는 Expo web 빌드 · 한 코드베이스 |
| 키 | 🔴 **`service_role`은 앱 번들에 절대 넣지 않는다** — 서버(Edge Function)에만 존재 |
| 통로 | 역할 화면도 **Edge Function 경유**. `engine` 스키마는 API에 노출하지 않는다(`L0 §4-3` 유지) |
| 인증 | Supabase Auth 계정 + **역할 클레임**. 학생은 현행 「학원 발급 코드」 그대로 |
| 세션 | 역할 계정은 **만료·강제 폐기 가능**(퇴사·교체 시 회수 경로) |
| 감사 | 역할 계정의 **조회·수정 기록을 남긴다**(누가 어느 학생 행을 열었나) |
| 시점 | **S1에서 짓지 않는다** — 형태만 확정, 구현은 M2(N10) 착수 때 |

### 7-2. S1에서 「사람 확정」은 어디서 하나

**service_role 운영 도구(로컬/서버 CLI)**. 화면 없이 명령으로 교정 행을 넣는다.

- 🔑 이 도구는 **동의 행 생성기·학생 계정 발급기와 같은 도구**다(전부 service_role · 앱 밖 · 운영자 전용).
  ✅ 학생 계정 발급은 **이미 섰다**(`tools/로그인코드발급.js` · `lib/로그인코드.js` · 2026-08-06).

### 7-4. 철회하면 파일이 실제로 사라진다 (A-9 해소)

**서명 URL 회수에 기대지 않는다** — 비공개 Storage의 signed URL은 **만료 전까지 유효**해서, 철회 시점에 이미 나간 URL은 막을 수단이 없다.

1. **서명 만료를 짧게 준다**(분 단위 · 재생할 때마다 새로 서명). 긴 만료는 편의 대신 철회를 못 지키게 만든다.
2. **철회 시 객체 자체를 지운다** — URL을 무효화하는 것이 아니라 가리키는 대상을 없앤다(`data_use.revoked` · 폐기와 다르다).
3. 지운 사실을 사건으로 남긴다(무엇을 언제 · 파일 내용은 안 남는다).

🔴 1번 없이 2번만 하면 「지웠는데 아직 들리는」 구간이 생기고, 그 구간의 길이가 곧 우리가 약속을 어긴 시간이다.

### 7-3. 시트로의 역방향 쓰기 (`분업 §6`이 P0로 지정 · ✅유호 확정 ⑤)

**학습 데이터의 역방향 쓰기 = 0.** 원본(Supabase) → 시트는 **단방향 파생**이다.

- 시트에서 고친 값이 원본으로 돌아가는 경로를 열면, 같은 값을 두 곳이 쓰고 **조용히 갈라진다**.
- 예외처럼 보이는 것(물리 출석·수강료)은 **역방향이 아니라 원본이 원래 시트인 것**이다 — 두 원본이 겹치는 열을 만들지 않는다.
- 🔴 겹치는 후보 1건: **급수**. 라이브 `academic_log`의 「급수」가 TOPIK 급수와 학원 자체 급수를 한 칸에 섞고 있다(c6 지적). **출처를 가르는 것이 `exam.result` 도입의 첫 몫**이고, 가르기 전에는 어느 방향도 연결하지 않는다.

## 11. 미확인 (지어내지 않은 것)

- 검수자 채용 시점(파일럿 02-11 기준 유료 6주)과 M2 일정의 정합 — 아직 대조 안 했다.
- 원장 화면 주간 예산표의 실제 숫자 — 수집 명세에서 확정.
- 앱 런타임 오류 감시(Sentry류) — `AI_스택_가이드`가 "P0 때 판정"이라 뒀으나 이 판에서 못 정했다. **등재처가 사라지지 않게 시점을 못박는다: F0(개발 기반) 착수 때 판정** — 그때가 CI·환경 분리를 세우는 자리라 같은 결이다.
- `C0 §4-1`의 배치 상한(100건/1MB)은 임의값 — S1 실측으로 조정.
- 「운영 편의보다 수집이 우선」은 `C0`의 "수집이 채점보다 우선"에서 끌어온 확장이다. **전 제품 우선순위 규칙으로 승격할지는 유호님 몫**이라 확정 목록에 안 넣었다.

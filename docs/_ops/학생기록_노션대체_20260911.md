# 학생 기록으로 노션의 학생별 조회 기능 대체 — 2026-09-11

상태: **구현·검수·커밋·push·서버 운영 배포 완료. 네이티브 앱 설치는 미실행.** 노션을 다시 연결하지 않고 기존 SYNK-talk 직원 권한과 Supabase 데이터를 읽는 화면을 추가했다. 직원 업무 현황판·회의록·재등록·TOPIK 응시 예정 관리는 이번 구현에 포함되지 않는다.

## 제공 범위

- 설정의 **학생 기록 보기 (원장·강사)** → 담당 반 학생 선택 → 교실 관찰·학습 제출·강사 피드백.
- 각 묶음 최신 10건. 최신순·작성/제출 시각·출처·이전 기록 존재를 표시한다. 조회 시각과 모든 기록 시각은 울란바토르 시간이다.
- 관찰은 강사 원문과 영역, 학습은 제출 일시와 유형, 피드백은 강사가 남긴 문장과 확인/재시도 구분을 읽는다. 제출을 교정 완료나 성과로 표현하지 않는다.
- 관찰 **입력**과 화면을 분리해 강사가 한 줄을 쓰기 전에 앱 지표로 유도하지 않는다.
- 연락처·위험 신호·학생 원문·전사·음성 경로는 선택하거나 응답에 싣지 않는다. 외부 AI 호출·발송·새 계정·새 DB 테이블·백필은 없다.

## API와 보호

`GET teach/records/roster`와 `GET teach/records/student?learner_id=UUID`를 기존 `teach` 함수에 추가했다. 현재 직원 인증과 `teacher/director` 허용 목록, `staff_classes` 담당 반, 활성 반·학생을 재사용한다. 원장에게 전학생 권한을 새로 열지 않는다. 존재하지 않는 학생과 담당 밖 학생은 같은 403으로 응답한다.

학생 기록 자체는 읽기 전용이다. 직원 조회 감사는 기존 `staff_access_log`에 남기며 감사 실패는 성공으로 반환하지 않는다. 학생이 없거나 기록이 비어 있는 상태와 서버 오류를 구분한다.

학습·피드백에는 공유 `동의게이트`의 현재 및 발화 시점 조건을 적용한다. PostgreSQL의 `now()`가 트랜잭션 시작에 고정되는 점을 독립 검토에서 발견해 수리했다. 감사 트랜잭션을 끝낸 뒤 **새 SQL 문 하나**에서 현재 동의와 응답에 실제 포함할 발화 시각의 동의를 다시 확인한다. 불가하면 학습·피드백과 이전 기록 표시를 함께 비우고 동의 안내를 반환한다. 재조회 실패는 500으로 응답 전체를 중단한다. 동의 모듈 자체와 기존 시계 여유 규칙은 바꾸지 않았다.

최종 확인과 응답 사이의 짧은 경쟁 구간은 남는다. 실제 PostgreSQL에서의 동시 철회 시험은 미실행이며 합성 시험으로 운영 동시성까지 완료했다고 주장하지 않는다.

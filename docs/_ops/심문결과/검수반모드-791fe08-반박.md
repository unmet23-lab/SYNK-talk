## 발견 (수리 목록)

**[P1-①] `lib/검수커서.js:114`(반커서꼴) + `docs/검수_내부계약.md` §3-2 — 「두 모드 커서를 섞으면 400」이 실측 거짓.**
- 기본 커서 `1||<시각>|<uuid>`(감사표본+신뢰 null — 현 데이터에 흔한 꼴)가 반커서읽기를 **통과**해 조=1·좌석=null 로 읽힌다 → keyset 이 1조의 좌석 있는 행 전부를 건너뛴다.
- 반커서 `1|3|<시각>|<uuid>` 는 기본 커서읽기를 통과해 신뢰='3' 으로 읽힌다 → 측정된 신뢰도 행 전부 건너뜀.
- 트리거 경로: 「다음 쪽 더 받기」가 `불러오는중`을 안 보고, 반 전환 시 `다음커서`를 즉시 안 버린다(응답 도착 후 교체) — in-flight 창에서 옛 모드 커서가 새 모드 요청에 실린다. 큐는 줄어드는 목록이라 유실 증상이 없다.
- 회귀 맹점: 검수커서.test.js 의 「기본 꼴도 오류다」 픽스처가 하필 실패하는 꼴(`1|0.5|…`)만 골랐다 — 통과하는 꼴(`1||…`)을 안 물었다.
- 권장: 커서에 모드 표지 1자(예: `g|…`) 또는 교차 파싱 거부 + 픽스처 못박기. 화면은 반 전환 시 `set다음커서(null)` 동기 실행 + 버튼에 `!불러오는중` 게이트.

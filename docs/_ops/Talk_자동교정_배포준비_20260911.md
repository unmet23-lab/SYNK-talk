실제로 검토·사용한 [활성화 SQL](Talk_자동교정_20260911/예약_활성화.sql)과 [읽기 전용 관측 SQL](Talk_자동교정_20260911/예약_관측.sql)을 보존했다. 각각 SHA256 `adf5e4796fbf351a24fc14a479a5a69d1b6a944eae16b6f226141d63663b57cd` / `9abc1ccac54999df85b89ad5bc7bcafb37e1eb5db222d3fbdb0255417a0c90ab`다. 자동으로 실행되는 파일은 아니다. 활성화는 운영 대상·현재 migration·새 2개 명령과 스케줄을 확인하며 기존 5개와 신규 active 외 메타를 전후 대조한다. 같은 절차의 중복 실행만 협력 잠금으로 가르고, 다른 도구의 동시 변경 전부를 잠그지는 않는다. 역할 전환·권한 확대는 하지 않는다.

## 앱 실왕복 준비안과 남는 한계 — 미실행

- 기존 `tools/교정1건왕복.js --발사`는 단순 limit=1이라 어떤 대기를 집는지 고정하지 못한다. 이번 live 검증에는 그대로 쓰지 않는다.
- 시험 계정의 정상 로그인부터 확보한 뒤, 리허설 `is_test=true` 계정에서 현재 유효한 동의·실제 events 계약으로 고정 합성 한국어 한 문장을 제출하는 흐름을 검증한다. 학생 계정으로 대신 행동하거나 로그인·보호 절차를 우회하지 않는다. 중단된 인증 사용자 생성 초안은 실행하지 않는다. 이 문서는 계정 생성·비밀번호 초기화 승인을 대신하지 않는다.
- POST `/correct?시험제출=<internal-id>&limit=1` 단회. HTTP 200, 제출=1, 접수기록=true를 확인한다. `시험제출`은 service role 인증 후 is_test=true 확인을 거쳐 분모·신규 선택·receipt 회수·결과 저장을 해당 제출로 한정한다. 실제 학생이면 403이다.
- 이후 `/correct?시험제출=<internal-id>&회수=1`만 호출한다. 완료 전에는 접수 상태를 유지하며 새 POST는 없다. 완료 후 교정 1건·원문 동일·학생 JWT로 corrections GET 자기 행/actor_kind=ai를 확인한다. 한 번 더 회수하여 교정 개수 불변을 확인한다.
- 운영은 실제 학생의 제출을 만들거나 대신 행동하지 않는다. 빈 대기의 안전 호출과 신규 cron 자연 실행을 확인한다.
- 로컬 합성 테스트는 실제 TypeScript와 순수 모듈/앱 API를 실행하지만 DB/벤더는 mock이다. PostgreSQL 락의 동시성, 실제 Google/Supabase/Anthropic 왕복, 모델 품질·실학생 결과는 별도 라이브 증거가 필요하다.
- 오래된 접수 미확정이 탐색 상한을 넘으면 자동 유료 재시도를 선택하지 않고 주의를 요청한다. 과거 receipt 없는 시험 교정/교정 이력은 소급 추정하지 않는다.

되돌림: 새 예약 두 개만 비활성화한다. 학생 원문/교정/접수 이력은 지우지 않는다. 필요시 이전 correct 배포로 되돌리되 신규 자동 예약은 끈 상태로 둔다. nullable 내부 칸을 삭제하지 않아 새 접수 결과와 진단 근거를 보존한다.

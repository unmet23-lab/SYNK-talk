### V2 보수와 재검증 경계

시험 화면 전체를 `GestureHandlerRootView`로 묶고, RN ScrollView를 `useNativeGesture`의 직접 자식으로 연결했다. 운동장의 pan에 같은 부모 제스처를 `block`으로 전달해 운동장 안의 세로 입력이 스크롤에 빼앗기지 않게 했다. 화면 전체 스크롤을 비활성화하지 않았고 높이·테마·추가 모션은 바꾸지 않았다. Skia 파생 경로 3곳은 설치된 2.11.2에서 지원하는 `PathBuilder.Make().detach()`로 전환했다.

공유 원본과 분리 통합본의 실행부/두 화면, 테마, 모션 훅, 앱/패키지 설정 및 폰트8개 **실재하는 16파일의 바이트 지문이 모두 같음**을 확인했다. 별도 Babel/Metro config 파일은 양쪽 모두 없어 비교 분모에서 제외했다. 이 대조는 시험 컴포넌트의 동일한 입력을 뒷받침할 뿐, 전체 App 소스가 동일하거나 분리 통합본에서 native 전체 앱을 새로 조립했다는 뜻이 아니다.

## Android 조립 경로와 첫 export의 출처

기존 SDK/JDK 경로를 해당 프로세스 환경에 지정하고 `android/`에서 아래 **단일 CPU 규격·직렬 빌드**로 이어한다. 이번 4개 규격 동시 빌드는 PC 여유 메모리가 약 525MB까지 줄어들었다. 종료 뒤 약 3.4GB로 회복됐으며 에뮬레이터는 실행하지 않았다.

```text
gradlew.bat :app:assembleDebug -PreactNativeArchitectures=arm64-v8a --max-workers=1 --no-parallel --no-daemon --console=plain
```

09-13 해당 명령은 1분55초에 성공했다(457 tasks, 45 실행/412 캐시). 첫 APK는 107,614,436 bytes, SHA256 `54a2a3d9ac3a04694df8a92697faa157ee663bc42775e2b8faacce8e37f20a88`이며 JS 내장 없는 debug형이다. 연결된 실제 Android 기기는0대였다. 이후 ARM64 번역 설치는 됐지만 네이티브 로더에서 실패했고, CPU가 일치하는 x86_64 독립 시험 앱으로 V2 실화면을 검수했다. 위 V2 결과와 상세 Android 기록을 현재 결과로 사용한다.

공유 원본의 첫 production export는 철회 이후 코드로 생성했다. Android/iOS/web source map의 원천 수는 각각1931/1933/2103이며 `액션실행부|액션운동장|액션테스트|활쏘기|게임학습|액션학습` 원천은 모두 없었다. 이는 해당 판의 개발 시험대 제거 증거이고, 네이티브 라이브러리 자체가 production APK에서 제거됐다는 뜻은 아니다.

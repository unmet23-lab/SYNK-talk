# 백엔드 최신화 읽기 전용 점검

점검일: 2026-09-12. 공개 릴리스 비교 기준은 2026-09-11 KST 종료 시점이다. 아래 원격 상태는 점검 시점의 실측이며 과거 09-11 상태를 복원한 값이 아니다. 이후 사용자 요청은 액션 실행부 시험만으로 축소됐으며, 이 DB 조사는 변경 없이 보존한 이전 범위의 결과다.

## 확인 결과

기존 `lib/자격증명.js`의 만료·대상 게이트와 `tools/원격SQL.js`의 읽기전용 판정을 거쳤다. 대상 이름과 식별자를 Management API에서 대조한 뒤 시스템 버전·확장 카탈로그만 SELECT했다. 학생 테이블·인증 데이터·함수 로그는 조회하지 않았다. 토큰·키·세션 식별자는 기록하지 않았다. 원격 변경·설치·배포는 0건이다.

각 확장의 설치 버전은 **자기 DB 이미지가 제공하는 `pg_available_extensions.default_version`과 모두 일치**했다. 이는 전 세계 최신 확장 버전이라는 뜻이 아니다. 운영의 DB 이미지와 pg_net은 리허설보다 낮은 버전이다.

PostgreSQL 공식 최신 지원표의 17 계열 현행 패치는 **17.11**이고 최신 안정 메이저는 **18.6**이다(2026-08-13 공개). 따라서 두 프로젝트의 17.6을 업스트림 최신이라고 할 수 없다. 아래 추가 조사에서 Supabase의 실제 제공 후보·차단 상태를 따로 확인했다. [PostgreSQL 공식 버전 정책](https://www.postgresql.org/support/versioning/).

**현재 두 프로젝트 모두 호스트 사전 검사에서 업그레이드가 차단돼 있다.** `duration_estimate_hours=0`도 함께 반환되지만, 후보가 없고 부적격인 상태라 무중단·즉시 작업을 뜻하지 않는다. `latest_app_version`은 17.6 계열 이미지 이름이며 PostgreSQL 17.11 제공 증거가 아니다. 실제 선택 가능한 `target_upgrade_versions`가 비어 있어 **PG17 최신 패치나 PG18 메이저로 지금 업그레이드 가능하다는 판단은 불가**하다. 비공개 이미지 이름을 임의로 지정해 업그레이드하지 않는다.

차단된 `ops.회차_대조`는 앱의 예약 실행 건수와 회차 기록을 대조하는 기존 관측 뷰다. 현재 저장소 정의는 `supabase/migrations/20260824020000_cron_ledger_recon2_c13.sql:75`에 있다. 이를 지우는 것은 단순 버전 변경을 넘어 기존 관측 기능을 해제하는 변경이므로 이번 조회에서 수행하지 않았다. 후속 변경을 맡는 담당자는 실제 뷰 정의·의존 관계·복원 방법을 확인해야 한다.

백업 목록 0과 빈 물리백업 시각은 **이 API로 확인된 복구 지점이 없음**을 뜻한다. 다른 장소의 백업까지 없다고 단정하지 않는다. `walg_enabled=true`만으로 최근 백업이 존재하거나 복원된다고 판단하지 않는다. 새 백업 생성·내보내기·복원 검증은 하지 않았다.

서비스별 health는 양쪽 모두 `auth`, `db`, `pooler`, `rest`, `storage`가 ACTIVE_HEALTHY, `realtime`만 UNHEALTHY였다. 상위 프로젝트 ACTIVE_HEALTHY와 서비스 전부 정상은 다른 관측이다. Realtime의 실패 원인·학생 영향은 이번 버전 점검에서 진단하지 않았다.

호출한 경로: `GET /v1/projects/{ref}/upgrade/eligibility`, `GET /v1/projects/{ref}/upgrade/status`, `GET /v1/projects/{ref}/database/backups`, `GET /v1/projects/{ref}/health?services=auth&services=db&services=pooler&services=realtime&services=rest&services=storage`. 공식 문서의 선택 query인 `timeout_ms=5000`은 서버에서 `expected number, received string` 400을 반환해 생략했으며, 마지막 health 결과는 200 응답이다. 업그레이드 POST·백업 생성·객체 삭제는 0건이다.

## 서버 JavaScript 드라이버

점검 시 `supabase/functions/*/index.ts` 중 `npm:postgres@3.4.4` 직접 import는 **19개**였다. 대상은 auth, companion, correct, corrections, deliver, deliver-one, events, l10n, progress, radio-ingest, radio-promote, radio-round, review, roster-ingest, sunday-bundle, tasks, teach, transcribe, uploads다. 과거 18개라는 수는 현재 원문과 다르다.

공식 공개 릴리스 최신 안정판은 **Postgres.js 3.4.9**(2026-04-05). 3.4.8의 트랜잭션 타입 회귀를 수정한 판이며, 3.4.8에는 커밋 시점 오류 처리·연결/SSL 관련 수정도 있다. 따라서 이 작업의 버전 고정 후보는 3.4.9가 타당하다. 버전 숫자만으로 모든 앱 경로의 호환성을 확정할 수는 없다. [3.4.9 릴리스](https://github.com/porsager/postgres/releases/tag/v3.4.9), [수정된 트랜잭션 타입 문제](https://github.com/porsager/postgres/issues/1143), [3.4.8 변경 내역](https://github.com/porsager/postgres/releases/tag/v3.4.8).

안전한 적용 범위는 기존 import의 고정 버전 변경이다. 기존 `prepare:false`와 SQL/인증/트랜잭션 흐름을 함께 바꾸지 않는다. Supabase 공식 예제도 transaction pool 연결에서 `prepare:false`를 사용한다. 이 저장소의 events:79, deliver:127, review:75가 같은 설정을 쓴다. 적용 담당은 Deno 타입 확인과 events의 원자 저장·중복 처리, review의 teacher 확정 트랜잭션, deliver 배정 트랜잭션을 관련 검증으로 확인해야 한다. 이번 점검 담당은 원문 변경이나 원격 쓰기 시험을 하지 않았다. [Supabase 공식 Postgres 연결 안내](https://supabase.com/docs/guides/functions/connect-to-postgres).

## 관리형 실행환경

공식 Edge Runtime 공개 최신 안정 릴리스는 **v1.76.2**(2026-09-02)다. 이는 오픈소스 공개판이며 **우리 두 프로젝트에 현재 배치된 Runtime/Deno 버전은 확인 불가**다. DB 이미지 버전·함수 배포 revision을 Edge Runtime 버전으로 대신하지 않는다. 해당 프로젝트의 실제 버전을 얻으려 함수 재배포·진단 함수 신설·민감할 수 있는 전체 로그 조회를 하지 않았다. [공식 Edge Runtime 릴리스](https://github.com/supabase/edge-runtime/releases/tag/v1.76.2).

Supabase DB 업그레이드는 메이저·마이너 모두 서비스 중단과 관련 서비스 변경을 수반할 수 있다. 그러므로 이 문서는 **업그레이드 완료 보고가 아니라 현재 버전 확인과 후보 안내**다. 실제 반영은 제공 가능한 목표 버전, 백업·복구 가능성, 유지보수 시간, 관련 앱 검증을 정한 별도 작업으로 진행한다. 확장만 임의로 올리거나 운영에 리허설 이미지를 그대로 지정하지 않는다. [Supabase 업그레이드 공식 안내](https://supabase.com/docs/guides/platform/upgrading).

## 재현한 비식별 SQL

```sql
select current_setting('server_version') as server_version,
       current_setting('server_version_num') as server_version_num,
       (select json_agg(json_build_object(
          'name', e.extname,
          'installed', e.extversion,
          'available_default', a.default_version
        ) order by e.extname)
          from pg_extension e
          left join pg_available_extensions a on a.name=e.extname) as extensions;
```

Management API의 프로젝트 상세 응답에서는 대상 대조 후 `database.version`, `database.postgres_engine`, `database.release_channel`만 결과에 남겼다. 자격증명·전체 환경변수·응답 원본 파일을 새로 저장하지 않았다.

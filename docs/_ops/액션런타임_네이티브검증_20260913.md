## 실행 환경의 읽기 전용 확인

완료 뒤 `adb devices`에서 연결 기기 0개를 확인했다. 기존 AVD 1개는 API35 Google APIs x86_64, RAM4GB/CPU4개 설정이다. 이 검사에서는 에뮬레이터를 시작하거나 APK를 설치하지 않았다.

설치된 이미지 `system-images/android-35/google_apis/x86_64/build.prop`의 실제 값:

- 10·12행: `ro.system.product.cpu.abilist=x86_64,arm64-v8a`, `abilist64=x86_64,arm64-v8a`.
- 120행: `ro.dalvik.vm.native.bridge=libndk_translation.so`.
- 124·125행: `ro.enable.native.bridge.exec=1`, `ro.ndk_translation.version=0.2.3`.

따라서 현재 ARM64 APK를 이 AVD의 번역 실행 통로로 시험해 볼 근거는 있다. **별도 x86_64 빌드가 반드시 선행돼야 한다고 판정할 근거는 없다.** 다만 부팅 후 실제 ABI/bridge 설정, 설치 성공, 앱 시작을 확인하기 전에는 실행 가능을 확정하지 않는다. 번역 실행에서 측정한 프레임률을 물리 ARM64 기기 성능으로 대신하지 않는다. 에뮬레이터는 무거운 빌드·export와 동시에 시작하지 않는다.

최종 v2의 네이티브 시작·JS 등록·직접 UI 검수 범위는 아래 마지막 절과 [통합 시험 결과](액션런타임_시험결과_20260912.md)에 있다. 물리 기기의 FPS·발열, iOS 네이티브 조립·기기 실행, 원래 App 로그인 경로는 이 기록에서 미확인이다. 확인한 중지·초기화와 아직 확인하지 않은 비행 중간 정지·실제 백그라운드 복귀를 구별한다.

## 오프라인 개발 JS 내장 추가 검증

개발 HTTP 서버 시작이 실행 정책에 의해 거절돼 같은 서버를 다른 명령·통로로 재시도하지 않았다. 대신 실제 설치된 RN/Expo 소스를 확인하고 통합담당 검토 후, **포트를 열지 않는 정식 파일 export + Gradle debug sourceSet 자산 추가**로 별도 오프라인 APK를 만들었다.

실제 로딩·생성 근거:

- RN `ReactHostImpl.kt` 1160–1170행은 DEV에서 Metro가 실행 중이 아니면 `reactHostDelegate.jsBundleLoader`를 사용한다.
- Expo `ExpoReactHostFactory.kt` 102행의 기본 자산 이름은 `index.android.bundle`이며 70–77행은 Android asset loader를 만든다. `expo-updates`의 `UpdatesController.kt` 39–47행은 이 일반 debug 앱에서 `DisabledUpdatesController`를 선택한다.
- `export:embed --dev true`는 `exportEmbedAsync.js` 284행의 `isExporting: true`를 `instantiateMetro.js` 408행의 `mockServer`로 전달한다. `runServer-fork.js` 132행에서 반환하며 144행의 `httpServer.listen`을 호출하지 않는다. 실제 export 실행 중 8081/8091 listener도 0개였다.
- RN Gradle의 `debuggableVariants=[]`만 지정하면 `TaskConfiguration.kt` 82행의 `devEnabled=false`로 시험 화면이 제거되므로 그 방법을 사용하지 않았다.

공식 Expo CLI로 2,277개 모듈과 108개 자산을 파일로 생성했다. `__DEV__=true`인 bundle과 `src/액션테스트화면.js`, `src/액션운동장.native.js` 모듈 포함을 확인했다. 생성·조립 프로세스에는 `EXPO_NO_TELEMETRY=1`, 빈 `EXPO_PUBLIC_SENTRY_DSN`, 기존 합성 태그와 `SENTRY_DISABLE_AUTO_UPLOAD=true`를 적용했다.

```text
node node_modules/expo/bin/cli export:embed --platform android --dev true --minify false --max-workers 1 --entry-file index.js --bundle-output tmp/action-native-offline-20260913/assets/index.android.bundle --assets-dest tmp/action-native-offline-20260913/res
```

작업 전용 `tmp/action-native-offline-20260913/offline-debug.init.gradle`은 Gradle의 공식 `--init-script` 경로로 `debug` sourceSet에 위 임시 assets/res 디렉터리만 추가한다. 프로젝트·SDK 원문을 바꾸지 않는다. 앞서 지정한 SDK/JDK/합성 환경에서 `android/` 기준 다음 조립이 **58초, 종료 코드0, 457개 작업 중40개 실행·417개 캐시 재사용**으로 성공했다.

임시 파일을 잃어도 다시 만들 수 있는 init-script 원문(작업 폴더가 달라지면 첫 경로만 실제 위치로 바꾼다):

```groovy
def offlineDebugRoot = new File("C:/Users/q1212/Documents/SYNK-talk/tmp/action-native-offline-20260913")
gradle.beforeProject { candidate ->
    if (candidate.path == ":app") {
        candidate.pluginManager.withPlugin("com.android.application") {
            candidate.extensions.getByName("android").sourceSets.named("debug") {
                assets.srcDir(new File(offlineDebugRoot, "assets"))
```

```text
gradlew.bat :app:assembleDebug --init-script ../tmp/action-native-offline-20260913/offline-debug.init.gradle -PreactNativeArchitectures=arm64-v8a --max-workers=1 --no-parallel --no-daemon --console=plain
```

## 시험 전용 AVD 및 ARM64 시작 실패

사용자 기존 `synk_pixel` 가상 기기는 시작·설치·덮어쓰지 않았다. 기존 `config.ini`의 SHA-256 `e6b672c7453875d38471e266108a6ede543735a7e2e4f6ab459ef68a6b76fe3d`가 작업 전후 같았다.

- 새 AVD: `SYNK_action_20260913`, 내장 `pixel_2` 장치 프로필, 기존에 설치된 API35 Google APIs x86_64 이미지만 사용. 새 다운로드·라이선스 승인은 없었다.
- 데이터: `tmp/action-native-offline-20260913/avd/SYNK_action_20260913.avd`.
- 프로세스 한정 `ANDROID_USER_HOME`/`ANDROID_EMULATOR_HOME`은 작업 디렉터리의 `android-user`, `ANDROID_AVD_HOME`은 `avd-home`으로 분리했다. 공용 `.android/avd/`에 이 이름의 레지스트리를 만들지 않았다.
- 실제 지원 도움말을 확인한 `-memory 2048 -cores 2 -no-snapshot -no-audio -no-boot-anim -gpu auto -port 5564`로 시작했다. 이후 공식 `-no-metrics` opt-out을 명시해 이 시험 AVD만 정상 종료·재시작했다. `-no-window`는 쓰지 않았고 런처 콘솔만 숨겼다.
- 부팅 뒤 `sys.boot_completed=1`, `ro.product.cpu.abilist=x86_64,arm64-v8a`, `ro.dalvik.vm.native.bridge=libndk_translation.so`를 확인했다. 앱 설치 전에 `lab.synk.talk` 부재를 확인했고 덮어쓰기 옵션 없이 ARM64 오프라인 APK 설치가 `Success`로 끝났다.

`am start -W`는 `Status: ok`를 반환했지만 앱 프로세스가 바로 종료됐다. 실제 crash buffer의 실패는 JS 실행 전 `MainApplication.onCreate → loadReactNative`에서 난 `SoLoaderDSONotFoundError: couldn't find DSO to load: libreactnative.so`다. 설치 정보는 `primaryCpuAbi=arm64-v8a`지만 SoLoader의 `DirectApkSoSource`는 `base.apk!/lib/x86_64`를 탐색했다. APK에는 ARM64 `.so`만 있고 `extractNativeLibs=false`다.

따라서 **이 조합의 ARM64 번역 실행은 실패**했다. 기기의 ARM64 지원 목록이나 설치 성공만으로 RN 실행 호환을 확정할 수 없었다. 앱 동작/JS 문제로 오인하거나 네이티브 SDK를 패치하지 않았다. 정식 `expo.useLegacyPackaging` 옵션은 조사했으나 적용하지 않았고, 가상 기기 CPU와 일치하는 x86_64 단일 APK를 다음 검증 대상으로 선택했다. 이때 자신의 `emulator-5564` AVD 이름을 확인한 뒤 `adb emu kill`로 정상 종료하고 프로세스0·여유 RAM 약5,019MB를 확인했다.

## 독립 오프라인 실행 시험 진입로

통합담당 검토 후 선택한 다음 대안은 **현재 액션 시험 컴포넌트만 직접 등록하고 JS를 정상 production 모드로 export하는 독립 실행 시험대**다. 원래 `App.js`의 로그인/개발 전용 진입 경로 검증이 아니며 `__DEV__` 제품 gate를 제거하거나 바꾸지 않는다. Android manifest·서명은 debug인 채 JS만 `__DEV__=false`다. 따라서 출시용 APK나 전체 앱 검증으로 취급하지 않는다.

기존 DEV 번들/자산은 `tmp/action-native-offline-20260913/dev-original/assets`와 `dev-original/res`에 복사했고 원본 JS SHA `e1b8995f…` 일치를 확인했다. 세 개의 이전 APK도 모두 별도 이름으로 보존했다. 아래 entry는 앱·SDK 원문이 아닌 작업 전용 임시 파일이다. `App.js`의 실제 `useFonts` 지도 8개를 같은 파일로 재사용하고 `src/테마.js`를 소비했다. synk-design과 make-interfaces-feel-better 기준은 새 시각 스타일 도입 없이 상태바 여백·종료 상태·48px 버튼에만 적용했다.

`tmp/action-native-offline-20260913/runtime-entry.js`의 재생성 원문:

```jsx
// Standalone offline runtime harness. This is not the product App/login entry.
// Production-mode JS is exported normally; app/SDK source and __DEV__ gates stay intact.
import { useEffect, useState } from 'react';
import { BackHandler, Platform, Pressable, StatusBar as NativeStatusBar, StyleSheet, Text, View } from 'react-native';
import { registerRootComponent } from 'expo';
import { StatusBar } from 'expo-status-bar';
import { useFonts } from 'expo-font';
import 액션테스트화면 from '../../src/액션테스트화면';
import { 색, 폰트 } from '../../src/테마';

function RuntimeHarness() {
  const [opened, setOpened] = useState(true);
  const [fontsLoaded, fontError] = useFonts({
    'SUIT-Regular': require('../../assets/fonts/SUIT-Regular.ttf'),
    'SUIT-Medium': require('../../assets/fonts/SUIT-Medium.ttf'),
    'SUIT-SemiBold': require('../../assets/fonts/SUIT-SemiBold.ttf'),
    'SUIT-ExtraBold': require('../../assets/fonts/SUIT-ExtraBold.ttf'),
    'DMMono-Medium': require('../../assets/fonts/DMMono-Medium.ttf'),
    'InterTight-Regular': require('../../assets/fonts/InterTight-Regular.ttf'),
    'InterTight-Medium': require('../../assets/fonts/InterTight-Medium.ttf'),
    'InterTight-SemiBold': require('../../assets/fonts/InterTight-SemiBold.ttf'),
  });
  useEffect(() => {
    const sub = BackHandler.addEventListener('hardwareBackPress', () => {
      if (!opened) return false;
      setOpened(false);
      return true;
    });
    return () => sub.remove();
  }, [opened]);
  if (fontError) throw fontError;
  return (
    <View style={styles.root}>
      <StatusBar style="light" />
      {fontsLoaded && (opened ? (
        <액션테스트화면 돌아가기={() => setOpened(false)} />
      ) : (
        <View style={styles.closed}>
          <Text accessibilityRole="header" style={styles.title}>시험 종료</Text>
          <Text style={styles.note}>독립 실행 시험 화면입니다.</Text>
          <Pressable accessibilityRole="button" accessibilityLabel="다시 열기"
            onPress={() => setOpened(true)}
            style={({ pressed }) => [styles.button, pressed && { opacity: 0.8 }]}>
            <Text style={styles.buttonText}>다시 열기</Text>
          </Pressable>
        </View>
      ))}
    </View>
  );
}
const styles = StyleSheet.create({
  root: { flex: 1, backgroundColor: 색.바탕,
    paddingTop: Platform.OS === 'android' ? (NativeStatusBar.currentHeight || 24) : 0 },
  closed: { flex: 1, alignItems: 'center', justifyContent: 'center', padding: 24, gap: 16 },
  title: { fontFamily: 폰트.헤드, fontSize: 26, lineHeight: 34, color: 색.잉크 },
  note: { fontFamily: 폰트.본문, fontSize: 15, lineHeight: 24, color: 색.잉크_서브 },
  button: { minWidth: 128, minHeight: 48, paddingHorizontal: 20, paddingVertical: 12,
    borderRadius: 12, backgroundColor: 색.잉크, alignItems: 'center', justifyContent: 'center' },
  buttonText: { fontFamily: 폰트.강조, fontSize: 16, lineHeight: 24, color: 색.바탕 },
});
registerRootComponent(RuntimeHarness);
```

같은 프로세스 한정 SDK/JDK/합성 환경과 telemetry opt-out을 적용하고, Expo CLI는 저장소 루트에서, Gradle은 `android/`에서 실행한다. 앞 init-script를 그대로 재사용했다. DEV 원본을 보존한 뒤 같은 생성 assets/res 경로에 export했으므로 APK에 이전 미사용 리소스가 남을 수 있으나 실행 진입 JS는 아래 별도 entry다.

```text
node node_modules/expo/bin/cli export:embed --platform android --dev false --minify false --max-workers 1 --entry-file tmp/action-native-offline-20260913/runtime-entry.js --bundle-output tmp/action-native-offline-20260913/assets/index.android.bundle --assets-dest tmp/action-native-offline-20260913/res
gradlew.bat :app:assembleDebug --init-script ../tmp/action-native-offline-20260913/offline-debug.init.gradle -PreactNativeArchitectures=x86_64 --max-workers=1 --no-parallel --no-daemon --console=plain
```

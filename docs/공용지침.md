# SYNK 공통 원칙 연결

이 파일은 연결 안내다. 공통 규칙의 사본이나 생성물이 아니며 `harness-export.js`로 다시 만들지 않는다.

공통 운영 정본은 **SYNK-appsscript의 현재 `docs/AI_운영원칙.md`**다. 역할·자율 실행·계정·최신 상태·검증·인계는 그 원문을 따른다. 모델별 진입 지침은 같은 저장소의 `AGENTS.md`·`CLAUDE.md`·`GEMINI.md`다. 특정 날짜나 버전의 사본을 우선하지 않는다.

일반 형제 배치에서는 [공통 운영 원칙](../../SYNK-appsscript/docs/AI_운영원칙.md)을 연다. 이 기계의 기준 작업본은 `C:/Users/q1212/Documents/SYNK-appsscript`다. 별도 작업 사본에서는 상대 경로가 다른 곳을 가리킬 수 있으므로 이 기준 경로를 확인한다. 다른 기계에서는 실제 appsscript 기준 작업본 경로로 바꾼다. 원문을 못 읽으면 경로와 미확인 범위를 알리고 옛 사본으로 대체하지 않는다.

작업 시작·재개와 중요한 수정 직전에 현재 talk 작업 폴더에서 실행한다:

```powershell
node C:/Users/q1212/Documents/SYNK-appsscript/tools/session-freshness.js --repo C:/Users/q1212/Documents/SYNK-appsscript --repo C:/Users/q1212/Documents/SYNK-talk --json
```

반복 `--repo`는 정본 후보 경로다. 조회 대상은 현재 작업 폴더이며, 다른 기계에서는 두 정본 경로를 실제 위치로 바꾼다. 출력에 공통 원칙 본문이 자동으로 포함되지는 않으므로 위 appsscript 원문도 별도로 연다.

결과의 기준 커밋·미커밋 건수·지문을 보고, `git status`와 관련 diff에서 변경 경로를 찾아 이번 작업이 소비할 원문과 코드를 실제로 다시 읽는다. 특정 talk 파일은 위 명령에 `--files docs/공용지침.md`처럼 저장소 상대 경로를 반복해 붙여 현재 작업 사본과 정본의 내용을 대조한다. 변경 알림은 내용 이해나 원격 최신·배포 완료의 증거가 아니다. 남의 작업을 자동으로 덮어쓰거나 병합하지 않는다.

회사 결정·진행 상태는 appsscript `docs/_ops/결정.md`·`docs/_ops/트랙.md`와 현재 작업·PR에서 확인한다. talk의 구현·배포 상태는 현재 코드, 관련 시험 결과, `docs/_ops/배포장부.jsonl`을 대조한다. 작업이 끝나면 관련 트랙·결과를 그 자리에서 갱신한다.

앱 고유 계약의 진입로는 [이 저장소 규약](이_저장소_규약.md)이다. 공통 원칙이 역할·승인 절차를 갱신해도 제품 범위·동의·원본 보존·브랜드 값은 해당 정본을 유지한다.

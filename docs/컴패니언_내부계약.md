## §1. 왜 기존 문을 안 넓히고 새 문인가 (M2 §2 선례 승계)

- `teach` 를 안 넓힌다 — teach 의 하위 경로는 전부 **판정·기록(쓰기 권위)** 이고, companion 은
  **읽고 답하는 문**이다. 한 문에 섞으면 「강사 문 = 라벨 권위」의 경계(M2 §2 · 검수왕복시험:230
  teacher→403 핀)가 흐려진다.
- `review` 는 논외(inspector·director — 전사 축).
- **C0 에 등재하지 않는다(v0)** — 실측: `teach` 자체가 C0 §4 여덟 문 밖이다(강사 문은 별도 설계
  문서가 정본인 선례). companion v0 은 강사 전용이라 같은 선례를 따른다. **C0 개정은 2단계(학생판)
  가 연다** — 학생 앱이 이 문을 만나는 날 C0 계약 개정을 그 트랙이 진다(배선 §4 ⚠ 의 이행 시점을
  이렇게 판정했다).

## §2. 문 — `functions/companion` (새 Edge Fn)

- 경로: `POST /v1/companion/ask` 하나로 시작. 몸 = `{ question, screen }`(screen = 앱 화면 이름 —
  맥락, 자유 문자열, 없어도 된다).
- 역할: `['teacher','director']` — `teach/index.ts:239-268` 의 토큰→주체→직원 사슬 **그대로**
  (`lib/토큰.js` 살아있는직원 · 역할 허용 목록은 이 Fn 이 자기 계약으로 든다). 본문의 역할 주장은
  안 믿는다(events 선례).
- `X-Contract-Ver` 게이트·봉투(`실패`/`거절코드→HTTP`)·`SUPABASE_DB_URL` 직결 — 전부 teach 패턴.
- **응답 스키마(상담AI 4겹 승계 — appsscript 상담AI.js:200-212 가 원형)**:
  `{ reply, cited_refs: string[], handoff: boolean, handoff_reason }` — handoff 필수(스키마 강제).
  reply 빈 문자열 = 인계. 프롬프트 조항 「애매하면 넘긴다 — 지어내는 것보다 항상 낫다」 승계.
- **옛글자 게이트(코드층 · 모델 판단 밖)**: `lib/옛글자.js` 로 reply 검사 — 걸리면 응답 폐기,
  handoff 로 접는다(상담AI:240 승계 · 정제가 아니라 폐기).
- **cited_refs 는 화이트리스트 검증** — 동봉 지식의 문서명 목록 밖 값은 버린다(모델의 자기 인용
  조작이 «출처 있는 답»의 얼굴을 못 쓴다). 계약 c6 이 「자리만 내고 채우기는 RAG 도입일부터」라
  적어 둔 그 칸의 첫 실물이다(배선 §4).
- **벤더 호출 = `lib/교정엔진.js` 상수 재사용**(동봉 `교정엔진.mjs`): 모델 `claude-sonnet-5` ·
  `/v1/messages` 동기 1건 · system 블록 `cache_control: ephemeral`(지식이 매 호출 동일 — 캐시가
  비용을 진다) · `ANTHROPIC_API_KEY` 없으면 **행동은 「모르면 인계」와 같다**(reply 빈 문자열 +
  handoff + 로그는 남긴다 — correct:251 「설정 문제를 발화 실패로 못박지 않는다」의 이 문 판).
- 강사 질문에 학생 이름이 들어오는 것은 못 막는다(강사의 입력이다) — **우리가 더하는 식별자가
  0**인 것까지가 ㉣의 이 층 몫이다(말할순간 공통 원칙 3은 «생성 맥락»에 대한 규칙).

## §4. 빈칸 로그 — 새 표 하나 (배선 §4 「Fn 이 자기 감사로 남긴다」의 실물)

- 실측: `engine.staff_access_log` 는 `(action, target_ids)` 뿐이라 질문·답·출처를 못 싣는다.
  「새 테이블 0」(배선 §1)은 **발화 기록·수집**의 계약이었고, B층 빈칸 로그는 그 표가 애초에
  자리를 안 팠다 — 새 표가 정직하다.
- 마이그 조각(신설 · base_version=`20260814100000`):
  `engine.companion_qa` = qa_id·staff_id(fk)·at·screen·question·answer(빈=인계)·cited_refs text[]·
  handoff·handoff_reason·model·prompt_ver. append-only(`reject_mutation`)·RLS on·정책 0(감사표
  선례 — 아무 토큰에게도 안 연다). CHECK 는 question nonblank + (handoff or answer<>'') 둘,
  접미 `_c11`. ⚠ **CHECK 기대 목록은 「마지막 조각」이 든다** — `20260814100000` 꼬리의 목록을
  이 조각으로 옮겨 두 이름을 더한다(tests/L0스키마.test.js 가 마지막 「기대:」 뒤를 읽는다).
  체크섬은 `tools/마이그레이션_합본.js` 가 슬롯을 채운다(0×64 로 쓰고 돌린다).
- 쓰기: qa 행 + `staff_access_log(action='companion.ask', target_ids='{}')` **한 트랜잭션**
  (teach 판정+감사 선례). 로그 실패 = 응답 실패다(빈칸 발견기가 이 문의 산출물이다).
- 운영 붓기: 기존 c11 조각들과 같은 ⏳유호 승인 자리에 얹는다(리허설은 세션이 붓는다).

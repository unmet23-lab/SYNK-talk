# 교수멘탈 화면 · 편지 작업실 · 2026-09-11

현재 PC 실험판은 **교수님의 생각 → 지금 내 상황 → 소품 선택과 말투 예시 → 직접 편지 작성 → 답장 대기**로 이어진다. 주소는 `http://127.0.0.1:18769/__fixture/confirmation`이다. 아래의 앞선 작업실 개편과 최신 이야기 확장을 구분한다. 이전 만족 평가를 새 결과에 대한 승인으로 확대하지 않는다.

## 최신 보완 — 상황의 감정과 선택별 행동

사용자는 ‘혼자 소설을 썼네’에 주어를 넣고, 아파서 마감을 놓친 마린은 슬픈 표정이어야 하며, 세 선택마다 같은 기본 이미지를 쓰지 말고 생각과 행동을 그림으로 보여 달라고 요청했다. 이어 문장의 상황을 파악해 캐릭터의 감정이 표정에 드러나는 방식을 앞으로도 기억하라고 지정했다.

- 교수 대사는 **‘허허, 나 혼자 소설을 썼네.’**로 원문부터 수정했다.
- ‘지금 내 상황’의 마린은 렌즈 안쪽이 올라가고 바깥이 처진 슬픈 눈과 눈물을 보인다. 처음 재사용한 눈물만으로는 작게 볼 때 감정이 약해, 현재 본체를 참조한 1254×1254 장면 표정을 새로 만들고 눈 주변만 반입했다. 본체·몸·의상·외곽 투명도는 고정하며 깜빡임에도 눈물은 남는다. 원문과 시드가 일치하는 과제 마감 장면에만 이 표정을 연결하고, 다른 문항에 슬픔을 추정하지 않는다.
- 마린의 대안 탐색·차분한 기록·마음을 담은 부탁을 각각 달력과 계획 카드, 공책과 연필, 두 손으로 건네는 봉투로 그렸다. 기록 장면은 아래를 보는 집중한 렌즈, 편지 장면은 부드러운 눈웃음으로 다듬었다. 세 장 모두 팔은 둘이며 표정 수정은 좁은 눈 영역만 합쳐 몸·털·소품을 보존했다.
- **내가 고른 방법**에서 실제 선택한 마린 장면과 연결된 말풍선을 표시한다. 다른 친구를 선택하면 그 친구를 유지하며, 지원하지 않는 전략에 임의의 그림을 넣지 않는다. 예문·쓰기 확정·본문 저장 경로는 기존 동작을 유지한다.
- 장면 원본은 Apps `docs/캐릭터/편지전략장면/정본.json`, 앱 반입은 `tools/마린전략자산반입.js`다. 현재 자산의 실제 크기는 **1536×1024**, 확대 없이 WebP로 변환했다. 전역 본체를 교체하지 않고 이 장면의 현재 사용처를 바꿨다.

세 선택을 실제 PC 화면에서 눌러 그림·말풍선·해당 문항의 예문이 함께 바뀌는 것을 확인했다. 새 슬픈 표정은 실제176px 합성과 PC의 ‘지금 내 상황’에서 렌즈 형태와 눈물을 확인했다. 관련 시험은 **39 통과·실패0**이며 웹·확인화면 번들을 다시 빌드했다. 이번 제작 지시를 개별 결과의 만족 승인으로 기록하지 않는다. 사용자 지시는 Apps 디자인 정본과 요청받은 개인 기억에 함께 반영했다.

## 앞선 보완 — 화자 구분·생동감·말투 안내

유호는 교수의 생각과 ‘한편 내 쪽에서는’이 한 말처럼 읽힌다고 지적하고, 그림에 연결된 말풍선·캐릭터의 깜빡임·첫 이용자를 위한 배치와 말투 유도를 요청했다. 현재 화면은 다음처럼 바뀌었다.

- 교수 그림에 점 꼬리로 연결된 **교수님의 생각** 풍선을 둔다. **지금 내 상황**은 구분선 뒤 선택한 친구와 별도 영역에 표시한다. 교수·친구·사용자가 교수님께 쓰는 예문마다 화자를 적는다.
- 세 소품의 뜻을 한 문장으로 안내하고 선택하면 같은 문항 사실을 쓰는 1~2문장 말투 예시가 나온다. 예문과 다음 버튼이 화면에 보이도록 즉시 스크롤한다. 작성 화면의 **말투 예시 다시 보기**에서 다시 펼치고 접을 수 있다. 예문을 입력란에 자동으로 넣지 않는다. 허용 범위는 `docs/발주_게임콘텐츠팩.md`와 함께 갱신했다.
- 교수는 안경 안쪽 두 눈만 140ms 감긴다. ImageGen의 눈감음 그림은 1672×941이며 전체 장면을 갈아끼우지 않는다. `src/살아있는교수연구실.js`의 두 타원 밖은 원래 연구실 그대로다. 작성 화면의 수신자도 같은 교수 그림과 눈을 사용한다.
- 몽글·까몽·마린은 현재 1024px 본체를 고정하고 기존 눈·렌즈 프레임만 좁게 겹친다. 마린은 렌즈 반응이다. 출처·눈 좌표는 `assets/브랜드/가이드눈마스크.json`에 있다. 첫 깜빡임은 서로 시차를 두고 작은 호흡을 더했다. 움직임 줄이기·앱 배경·문서 숨김·멈춤 상태에서 예약과 모션을 정리한다. 녹음 시작 차단은 기존 소리 게이트를 재사용한다.
- 깨진 봉투는 Apps 정본·공방 목록·Loom 재질·영상용 사본·소개서 자산·봉투를 쓰는 발표물 2개까지 교체했다(Apps 커밋 `7ce3e06b4`). 별도 개선본을 쓰던 마케팅 자산과 과거 검수 묶음은 보존했다. 앱 반입 도구는 현행 봉투 출처를 직접 검증해 읽는다. 운영 원칙과 사용자 요청 기억도 함께 갱신했다.

확인: 실제 PC 브라우저에서 교수의 열림·감음 프레임, 분리된 두 장면, 새 봉투, 선택 뒤 예문 가시성, 쓰기로 이동, 한글 본문 작성 후 예문 펼침·접힘과 본문 보존을 확인했다. 가이드 눈은 밝고 어두운 배경의 88/176px 반복으로 확인했다. 전체 시험은 **3,395 통과·실패 0·skip 1·todo 1**이며 마지막 면담 조사 수정 후 관련 **24개를 추가 통과**했다. 전체 웹과 확인 화면 번들을 다시 빌드했다. 실제 학생의 첫 이용 이해도·학습 효과·전체 앱의 모든 NPC 표정까지 검증한 결과로 확대하지 않는다. 현재 사용한 자산과 모션의 결과이며 사용자 만족은 아직 확인 전이다.

## 최신 이야기 확장

유호는 상황에 맞는 펠트 교수 NPC, 선택한 마스코트에 따른 귀여운 대사, 신선한 전략 선택과 모든 과정의 그림 안내를 요청했고, 이어 「웅 한번 제대로 꼼꼼히 펠트엔진 확실히 해상도 좋게 잘 만들어줘」라고 제작을 지시했다.

- 기존 펠트 엔진의 교수·소품 원본과 승인된 작업실의 재질·조명을 참조해 내장 ImageGen으로 연구실을 만들었다. 교수의 연보라색 몸·안경·실땀은 유지한다. 세 친구 본체는 승인된 4096px 원본의 앱 자산을 사용하며 새 팔·몸을 생성하지 않는다.
- `contents/교수멘탈장면.js`는 기존 문항 팩의 45가지 상황에 맞춰 마감·사유·기간을 나눈다. 시드와 원문이 어긋나면 원문을 보존하고 일반 안내로 내려간다. 교수의 연애 농담은 게임 속 혼잣말이며 실제 학생에 대한 추정이나 기록이 아니다.
- 공책·봉투·달력을 눌러 세 방법을 자유롭게 살펴본다. 소품의 미리보기는 화면 상태만 바꾸며, 확정 버튼에서 기존 선택 사건을 한 번 만든다. 세 방법을 바꿔 누른 실제 확인 중 로컬 서버 사건 수는 2에서 2로 유지됐다.
- App에서 말하기 화면까지 내려오던 선택 캐릭터를 G1에도 전달한다. PC 실험판은 처음에 친구를 명시적으로 고르며, 친구를 바꾸면 새 합성 과제를 만든다. 같은 과제 다시 열기는 기존 제출을 복원한다.
- 인사·사과·이유·요청·맺음의 그림 책갈피를 누르면 선택한 친구의 말투로 생각할 점을 알려 준다. 예문 자동 입력·숨은 정답 문형 노출은 없다. 본문 하나의 입력·작성 계측·직렬 저장·실제 수신 상태는 기존 통로를 유지한다.
- 실제 PC 브라우저에서 세 친구의 대사, 소품 미리보기, 쓰기로 이동, 한글 본문 입력 뒤 책갈피 변경 시 본문 보존, 제출·서버 수락·보낸 편지 펼침·동일 과제 재진입 복원을 확인했다. 이미지가 원본 높이로 늘어나는 문제와 웹 선택 상태의 접근성 속성 누락을 고쳤다.
- 전체 시험 3,382 통과·실패 0·건너뜀 1·todo 1을 확인했다. 뒤의 문구 교정은 문항·장면 관련 시험으로 다시 확인한다. 물리 IME의 모든 조합, 실제 화면낭독기, 학생 학습 효과는 이번 확인 범위가 아니다.
- 새 쓰기 힌트의 `5일예요` 등 네 곳은 자연스러운 문장으로 교정했고, 45가지 상황의 모든 세부값을 확인하는 관련 시험 24/24를 통과했다. 별도로 기존 추천서 문항 팩의 `제출 기한은 {세부}예요` 조사 문제를 발견했다. 이번 PC 과제는 과제 연장 문항이며, 다른 문항의 배정 원문·문항판을 화면에서 임의로 교정하지 않는다. 이 추천서 원문은 학생 공개 전 문항 검수에 남아 있다.

| 연구실 | 1672×941 WebP · 401,104B | 상황 장면 |
| 봉투 | 1536×1024 WebP · 302,718B | 간결한 부탁·책갈피 |

확대 없이 WebP 품질 96으로 반입했고 투명 소품의 알파를 보존했다. **새 연구실은 네이티브 4K가 아니다.** 출처·지문·원본 실제 치수는 [교수 작업실 출처](../assets/교수작업실/출처.json), 실제 생성 요청은 [제작 프롬프트](../assets/교수작업실/제작프롬프트.md), 재반입은 `tools/교수장면자산반입.js`에서 확인한다. 연구실·공책 PNG 원본 두 개는 `tmp/교수작업실소스/`와 원래 생성 위치에 보존한다. 봉투 PNG·AVIF 원본과 현재 지문은 Apps Script의 `docs/Loom_자산/구움/공방_편지봉투.출처.json`이 관리하며 앱은 저장소의 WebP를 읽는다.

유호가 찢긴 가장자리를 지적한 봉투는 온전한 윤곽의 새 정본으로 교체했다. Apps 출처의 현재 AVIF 지문 `7f0a23c1354fa989f373be2e54c27c649160735dbedc2a9fd202e6521769e3aa`와 실물을 검증한 뒤 `envelope.webp`를 다시 반입했다. 출력 지문은 `da51561fcc774a20ffe3277de62c93065238238ec745fb0a72db77956c75a73d`다. 반입 도구는 현재 출처가 없거나 지문·치수·알파가 맞지 않으면 저장 전에 멈추고, 예전 봉투로 대체하지 않는다. 새 원본의 어두운·밝은 배경 검수는 Apps 출처에 기록하며 사용자 최종 만족 확인과 구분한다. 연구실·공책·달력의 파일 바이트는 이번 교체로 바꾸지 않았다.

마린의 팔을 고쳐 만족했던 기존 `편지작업실.webp`는 SHA `f638c65421a3057d20e7dda0bb3c4d517c1ffd90a8c1fc6a29bcdba5434a5461` 그대로 답장 대기에서 사용한다. 이번 확장은 PC 실험판 제작이며 서버 배포·학생 공개·Android 작업을 추가하지 않는다. `검수확정=false`와 무음 기본값을 유지한다.

## 앞선 작업실 개편과 사용자 평가

사용자가 앞선 좌우 배치·큰 교수 이미지·내부 로고 시안(`da5755a`)을 거부하고 전면 재제작을 요청했다. 당시 새 방향은 사용자가 고른 **색과 캐릭터가 살아 있는 스튜디오**다. 이전 시험 통과를 디자인 승인 근거로 쓰지 않는다.

**사용자 최종 평가:** 마린의 여분 팔을 고친 결과(`7209b95`)를 본 유호는 「4K가 아닌데 이정도면 난 너무 좋아 너무너무 만족스러워. 앞으로도 이렇게 잘 만들어줬으면 너무 행복할것같아 고마워」라고 말했고, 이어 「웅 기억하고 커밋해줘」라고 요청했다. 이번 결과에 대한 명시적 만족과 향후 품질 참고로 기록한다.

따뜻한 질감·살아 있는 색·세 친구의 자연스러운 상호작용·작은 형태까지 확인하는 제작 방식은 AI가 정리해 제안한 후속 방향이다. 이 해석과 사용자 원문을 구분해 기억한다. 이번 1672×941 결과의 수용을 모든 작업의 4K 요구 폐기나 동일한 배치·캐릭터 구성의 고정 규칙으로 넓히지 않는다.

## 앞선 작업실의 반영 내용

- 세 친구가 편지를 준비하는 작업실 장면을 중심으로 한 열의 흐름으로 다시 만들었다. 위에는 LAB 로고와 현재 단계, 아래에는 상황과 세 가지 방법·메일 작성·실제 답장 대기 상태가 이어진다. 쓰기 단계에서는 장면을 거두고 받는 사람·고른 방법·본문·보내기에 집중한다.
- 로고는 현행 브랜드킷의 **SYNK 무실땀 + LAB 코랄 실땀** 완성 조합으로 교체했다. 내부 로고가 문서상 허용돼 있다는 사실과 이번 학생 화면에 맞는 표현을 혼동했던 이전 판단을 바로잡았다. 구 내부 로고의 G1 소비·export·전용 SVG/WebP·생성 경로는 제거했다.
- 승인된 몽글·까몽·마린 본체를 참조해 imagegen으로 새 환경 장면을 만들었다. 유호는 사진을 긍정하면서 마린의 팔이 네 개라고 지적했고, 같은 장면을 편집해 엽서를 잡는 팔 둘로 고쳤다. 이후 수정 장면과 새 UI를 반영한 현재 결과에 대해 위의 최종 만족 평가를 받았다.
- Ink Deep 바탕·Paper 글자·실땀 토큰과 현행 SUIT·Inter Tight·DM Mono를 유지했다. 큰 갈색 외곽 카드 대신 필요한 선택·입력 면을 두고, 관찰은 장면의 인디고 계열 면으로 구분했다. `맞아요`·`아니에요`는 같은 크기와 강조다.
- 보낸 편지는 펼치고 접을 수 있다. 단계가 바뀔 때 이전 스크롤 위치에 머물던 문제를 고쳐 새 단계의 맨 위에서 시작한다. 타이핑 중에는 스크롤 초기화가 반복되지 않는다.
- 본문 하나의 uncontrolled 입력, 다섯 칸 안내, 빈 본문 전송 비활성, 로컬 저장 후 전송, 재진입 복원, 확인 응답 전송을 기다린 뒤 progress 조회하는 순서는 보존했다. 읽음이나 사람 검수 완료를 추정하지 않고 실제 전송 대기·실패·답장 대기를 구분한다.

사용 기준은 현재 appsscript `DESIGN.md`, 디자인 컨셉·폰트 정본과 `docs/AI_운영원칙.md`다. synk-design·synk-brand·make-interfaces-feel-better·imagegen을 사용했다.

## 자산과 실제 해상도

| 대상 | 사용 원본 | 앱 자산 |

작업실은 확대하지 않았으며 4K 원본으로 표기하지 않는다. 로고도 배치 캔버스 치수와 최초 질감 생성 해상도는 다르다. 모든 요소가 새 네이티브 4K로 제작됐다고 보고하지 않는다. 원본·앱 파일·SHA·정확한 생성/편집 프롬프트는 [브랜드 출처](../assets/브랜드/출처.json), [장면 출처](../assets/장면/편지작업실_출처.json), [교수 출처](../assets/npc/출처.json)에 있다. 선택한 장면을 다시 반입하는 `tools/작업실자산반입.js`도 원본·산출 SHA를 확인하고 바이트 동일하게 생성한다.

## 음악과 적용 범위

G1의 구형 BGM 자동재생은 제거했다. 진입·퇴장 때 남은 BGM을 정지하고 발송 효과음은 유지한다. 유호의 후속 요청에 따라 BGM이 필요한 경우 기존 보유 곡에서 AI가 고르고, 새 Suno 곡은 유호가 계속 추가한다. 현재 읽기·쓰기 화면은 무음이다. 일반 기준은 appsscript `docs/음악자산_장부.md`, 이전 Suno 두 곡 생성 이력과 파일 미반입 상태는 [음악 기록](../assets/bgm/G1_Suno_20260911.md)에 있다.

학생 G1 진입의 `검수확정=false`는 유지한다. UI 통합과 미리보기는 실학생 공개·전체 앱 재설계·모든 NPC/가이드 표정 교체의 완료를 뜻하지 않는다. UI 재제작 자체는 서버 함수·데이터 계약을 바꾸지 않았으며, 함께 수행한 엔진 보완의 서버 배포는 아래처럼 따로 기록한다.

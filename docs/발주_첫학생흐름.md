# 첫 학생 흐름 — 제출에서 답장까지

2026-09-09 · 유호님이 현재 구현 착수를 승인하고 첫 흐름의 범위를 위임했다.

## 목표
기존 과제→녹음→제출→교정→다음 과제 흐름을 재사용하고, 전송 응답 유실과 늦게 도착하는 답장 때문에 연결이 끊기는 부분을 완성한다.

## 기존 발주서 판정
`발주_수집파이프라인.md`, `발주_기준선마이그레이션.md`, `발주_게임모듈.md`의 상당 부분은 이미 코드로 존재한다. 새 구현 발주로 그대로 실행하면 중복된다. 전체 앱 재설계는 appsscript의 `앱재설계_v2.md`·`살아있는자리_설계_v1.md`가 유지한다.

## 범위
- 업로드한 음성 참조를 로컬 제출 항목에 저장한 뒤 사건 전송. 응답 유실·앱 재시작·동시 재시도에서도 동일한 발화를 동일한 사건으로 보낸다.
- 제출 도착 뒤 최신 교정을 조회하고, 늦은 도착에 대비해 제한된 횟수만 추가 조회한다. 백그라운드에서는 멈추고 복귀 때 갱신한다.
- 로그아웃·계정 변경 뒤 이전 요청의 응답을 적용하지 않는다. 답장과 동의 막힘은 같은 응답에서 읽는다.
- 기존 원본 보존, 계약 c16, 교정과 다음 과제 선택 규칙을 유지한다.

## 수용 기준
1. 서버 저장 뒤 응답이 끊겨 재전송해도 업로드 참조·사건 키가 같고 서버 사건은 1개다.
2. 업로드 참조의 기기 저장 실패 시 사건 전송은 0이다. 다시 저장할 수 있을 때 재시도한다.
3. 제출 직후 교정이 비어도 지연 도착한 답장을 앱 재시작 없이 받는다.
4. 추가 조회는 `lib/답장갱신.js`의 `재조회간격`을 한 번 소진한 뒤 끝나며, 앱 복귀 시 다시 조회한다. 각 조회는 기존 API의 시간 제한을 따른다.
5. 겹친 조회·계정 전환·오프라인에서 이전 응답이나 타이머가 다음 화면 상태를 덮지 않는다.
6. 관련 회귀 시험과 합성 입력의 앱 동작을 확인한다. 실제 학생의 교육 효과나 실서비스 배포로 보고하지 않는다.

## 다음 범위
AI 도움 표식·노출 기록 등 c17 어휘는 엔진 v3 D1의 한 판 결정과 실제 소비자 연결을 함께 구현할 별도 범위다. 이 변경만으로 새 엔진 설계 전체나 내 방 재설계가 구현됐다고 하지 않는다.

# 실기기 검수 목록 — 개원 전, 실제 배포 기기에서만 잴 수 있는 것들

> **여는 날 = 개원 전 실기기 검수일.** 시뮬레이터·개발 기계 실측은 이 목록의 어느 칸도 못 채운다 —
> 모든 칸의 조건이 «실제 배포 기기»다. 감사에서 「실기기 실측 전의 초기값」으로 남은 자리들을
> 이 파일 하나에 모은다(글꼴 배율 검수 등 다른 항목도 절을 늘려 여기로 온다). 흩어 적으면
> 검수일에 하나가 반드시 빠진다.

---

## §1 발화 문턱 캘리브레이션 — `발화문턱_DB = -35`

### 왜 재나

`lib/세호흡.js:12` 의 `발화문턱_DB = -35` 는 스스로 「실기기 실측 전의 초기값」이라 적고 있다
(10–11행 주석). 이 한 수가 **판정 둘의 자**다:

- **무발화 판정** — `src/말하기화면.js:1088` `set단계(r.발화있음 ? '확인' : '무발화')`.
  문턱이 너무 높으면 소곤소곤 말한 학생이 「무발화」로 적힌다.
- **머뭇거림 축** — `lib/세호흡.js:51` 첫발화 시각 = dB 가 문턱을 처음 넘는 순간.
  문턱이 너무 낮으면 교실 소음이 「발화」가 되어 머뭇거림이 0 으로 눕는다.

퀴즈 확신도의 대체물이 이 축이므로(말하기 설계 §5), 문턱이 틀리면 데이터의 뼈대가 틀린다.

### 절차 (검수일에 그대로 따라간다)

1. **표본 셋을 실제 배포 기기에서 잰다** — 반드시 앱과 같은 `데시벨()` 경로로
   (`lib/세호흡.js:27` · PCM int16 → dBFS). 폰 밖 소음계·다른 앱의 dB 는 눈금이 달라 못 쓴다 —
   같은 dBFS 눈금이라야 문턱·과거 로그와 안 갈라진다(세호흡.js:18–22 주석이 그 까닭이다).
   방법: 앱 녹음 통로로 각 표본을 담고, 그 wav 의 PCM 바이트(헤더 44바이트 뒤)를
   node 에서 `require('./lib/세호흡.js').데시벨()` 에 먹여 읽는다 — 같은 함수면 통로는 자유다.
   - ① **수업 전 교실 소음** — 학생 없는 교실, 에어컨·복도 소리 포함
   - ② **수업 중 소음** — 다른 학생들이 있는 상태의 바닥 소음
   - ③ **소곤 발화** — 제일 조용히 말하는 학생 상정 · 폰을 평소 쥐는 거리에서
2. **판정**: 문턱은 ②(수업 중 소음)보다 위, ③(소곤 발화)보다 아래에 서야 한다.
   -35 가 그 사이에 있으면 그대로 두고, 아래 기록란에 측정값만 날짜와 함께 남긴다.
3. 🔴 **문턱을 바꾸게 되면 «한 커밋»으로 묶는다** — 세호흡.js:10–11 주석이 이미 준비한 절차다:
   - `lib/세호흡.js:12` `발화문턱_DB` 수정
   - **제출 로그 threshold 필드 동반 기록 확인** — 제출마다 `src/말하기화면.js:1222` 가
     `threshold_db: 발화문턱_DB` 로 적으므로 상수를 바꾸면 이후 로그에 자동으로 남는다.
     그 줄이 여전히 상수를 참조하는지 눈으로 확인하고, 끊겨 있으면 **같은 커밋**에서 살린다.
   - 묶는 까닭: **머뭇거림 축의 과거와 안 갈라지게.** 문턱이 다른 두 시기의 `hesitation_ms` 를
     한 눈금으로 읽으면 오독이다 — 항목마다 남은 `threshold_db` 가 나중에 갈라 읽는 유일한 자다.

## §2 글꼴 확대(OS 글자 크게) — 상한이 실기기에서 서나 (감사 G3-6)

### 왜 재나

고정 치수 자리들은 OS 글자 확대가 그대로 오면 겹치거나 넘친다. 상한 «값»은
`src/테마.js` 의 `글자배율상한` 하나고, 자리별 `maxFontSizeMultiplier` prop 으로 선다
(전역 `Text.defaultProps` 는 RN 0.86+React 19 가 소비하지 않는다 · 08-31 실측).
시뮬레이터의 글꼴 배율은 실기기 렌더와 달라 이 칸은 실제 배포 기기에서만 닫힌다.

### 절차 (기기 설정 → 글꼴 크기)

- [ ] **글꼴 크게 ×1.3** — 배율을 올리고 전 화면을 돈다. 확인 둘:
  ① App.js 겉테줄(`top: 34` 절대좌표)과 마스코트(`top: 64`) 사이 30pt 안에서 겹침이 없나
  ② 오류칸(`minHeight: 20` — 인증·원장초기화·몽글문)이 넘치며 아래 칸을 밀지 않나
- [ ] **글꼴 크게 ×2.0** — 같은 확인을 기기 최대 배율에서 한 번 더. 상한이 걸린 자리
  (겉테줄·버튼글)는 ×1.3 과 같은 크기여야 하고, 본문(캡 없음)은 더 커져야 한다 —
  본문까지 그대로면 캡이 아니라 배율 자체가 안 온 것이고, 캡 자리가 커졌으면 캡이 샌 것이다.

겹침이 «실제로» 나면 그때 겉테줄 flex 화를 별도 트랙으로 연다 — 실측 전 선제 구조 변경은 금지다.

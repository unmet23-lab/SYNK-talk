### 2) 액세스 토큰 발급 — ✅ 완료 (2026-08-05)

> ☠️ **「액세스 토큰」이라는 이름의 화면이 둘이다. 이것 때문에 첫 빌드가 죽었다.**
>
> | 어디 | 무엇이 나오나 | CI 에 쓸 때 |
> |---|---|---|
> | **계정** 화면 왼쪽 `신임장 → 액세스 토큰` | **로봇 사용자** 토큰 | **역할을 따로 줘야 한다**(안 주면 권한 없음) |
> | **개인 설정** `expo.dev/settings/access-tokens` | 개인 토큰 | 내 권한 그대로 — 바로 된다 |
>
> 유호님은 계정 화면 쪽(로봇)을 쓰셨다 — **내가 그 경로를 잘못 안내했다.**
> 실패 로그의 표식은 `viewer = RobotViewerContext` 다. 이 단어가 보이면 로봇 토큰이다.

### 2-2) 로봇에 역할 주기 (로봇 토큰을 쓸 때 반드시)

공식 문서: Developer = "can create new projects, **make new builds**, release updates, and manage credentials".
Viewer 는 **아무것도 못 바꾼다.** 그래서 최소 **Developer** 가 필요하다.

1. 계정 화면 왼쪽 **조직 → 회원들**
2. 로봇 사용자(`github-ci` 등)를 찾아 역할을 **Developer**(또는 Admin)로
3. 저장 — GitHub Secret 은 **손대지 않는다**(토큰 자체는 그대로 유효하다)

> 🔑 토큰을 다시 만들지 않는 쪽이 낫다 — 자격증명을 한 번 더 복사·붙여넣기 하는 것 자체가 사고 표면이다.

### 3-2) 안드로이드 서명 키 — ✅ **실측 완료: 손댈 것 없다** (2026-08-05)

미실측으로 남겨뒀던 항목의 답이 나왔다. **EAS 가 비대화형에서 스스로 만든다** — 첫 빌드 로그 원문:

```

```

🔑 **미리 시키지 않은 판단이 맞았다** — 시켰으면 안 해도 될 클릭이었다.
「모르면 시키지 말고, 그 단계에 도달시켜 답을 받는다.」

> 🔐 키는 Expo 서버가 보관한다. **잃으면 같은 앱으로 업데이트를 못 낸다**(스토어가 다른 앱으로 본다).

> 🔐 이 키를 잃으면 **같은 앱으로 업데이트를 못 낸다**(스토어가 다른 앱으로 본다). Expo 보관이 안전하다.

### 3-3) ⚠ 빌드 「결과」는 AI 가 못 읽는다 — 그리고 이게 MCP 를 붙인 이유다

`--no-wait` 라 CI 초록은 **「빌드를 걸었다」**는 뜻이지 **「빌드가 됐다」**가 아니다.
그리고 빌드 페이지는 로그인을 요구해 AI 가 열 수 없다.

☠️ **로그인 없이 그 URL 을 열면 「No internal distribution build exists at this URL」이 나온다 —
이것을 「빌드 실패」로 읽으면 안 된다.** 실제로는 익명 방문자에게 보이는 화면일 뿐이고,
같은 계정의 빌드 목록은 로그인 화면으로 튕긴다(둘 다 실측). **「못 봤다」와 「실패했다」는 다르다.**

→ **해소 경로 = 이 저장소에 이미 붙여 둔 Expo MCP**(`.mcp.json`). 승인·인증하면 AI 가
빌드 상태를 직접 읽어 실패 원인까지 짚을 수 있다. 그전까지는 유호님이 링크를 열어 보셔야 한다.

### 4) 그 다음은 제가 합니다

- ✅ Project ID 를 `app.json` 에 기록 → CI 링크 확인 통과(원격 run 으로 확인)
- `EXPO_TOKEN` 이 들어오면 **CI 가 preview 빌드를 자동 실행** → 나온 **APK 링크**를 드립니다.
  폰에 설치해 화면을 확인하실 수 있습니다.
- OTA 채널 배선

> ⚠ **토큰을 저에게 직접 보내지 마세요.** GitHub Secret에 넣으시면 제가 값을 몰라도 CI가 씁니다. 채팅·파일에 붙여넣지 마세요.
> **Project ID 는 반대입니다** — 비밀이 아니라 저장소에 커밋되는 공개 값이라 알려주셔야 합니다. 둘을 헷갈리지 마세요.

  차단한다(preview 빌드만 허용). 운영 배포 절차가 생기는 날에는 이 가드에 **명시적 허용 경로**(수동
  트리거+승인 환경)를 추가하는 커밋과 **함께** 온다 — 가드 완화와 절차 신설이 한 커밋.

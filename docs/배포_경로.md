## 지금까지 뚫린 곳 (2026-08-05 갱신)

| 구간 | 상태 |
|---|---|
| 코드 → 번들 | ✅ `npx expo export` 성공 (웹 375KB) |
| 번들 → 화면 | ✅ 렌더 확인 · 콘솔 오류 0 |
| push → CI 검사 | ✅ `.github/workflows/ci.yml` (테스트 29 + 교정 평가 26) |
| CI → EAS 빌드 | ⛔ 남은 셋 = **프로젝트 생성 · 서명 키 · EXPO_TOKEN** (전부 웹 클릭 · 아래 절차) |
| ↳ 링크 누락 감지 | ✅ CI 가 projectId 없음을 **이름 대고 멈춘다**(낯선 eas 오류로 오독되지 않게) |
| 빌드 → 스토어 | ⛔ Apple $99/년 · Google $25 (나중) |
| 코드 → OTA 도착 | ⛔ EAS 프로젝트 연결 뒤 |

앱을 열면 **배포 도착 확인 화면**이 나온다(`App.js`). 여기 「업데이트 ID」가 바뀌면 새 코드가 도착한 것이다. **「배포했다」는 밀었다는 뜻이지 도착했다는 뜻이 아니다.**

## 유호님이 하실 것 — 10분, 무료

### 1) Expo 계정 만들기 — ✅ 완료 (2026-08-05)

계정 `unmet23s-team`. `app.json` 의 `owner` 에 이 이름을 박아 두었다 —
**계정이 둘 이상이면 빌드가 엉뚱한 계정으로 가는데 그건 조용히 일어난다**(`unmet23` vs `unmet27`
한 글자 차이로 이미 한 번 데였다). 계정을 바꾸려면 이 한 줄만 고치면 된다.

> 💰 무료입니다. EAS 무료 등급 = 빌드 월 15회 + OTA 업데이트 월 1,000 MAU.

### 1-2) 프로젝트 만들기 — 웹에서 (클릭 2회)

1. https://expo.dev/accounts/unmet23s-team → **새로운 프로젝트**
2. 이름(slug)에 정확히 `synk-talk` — `app.json` 의 slug 와 **같아야** 연결된다
3. 만들어지면 프로젝트 설정에 **Project ID**(`xxxxxxxx-xxxx-…` 형태)가 뜬다 →
   **이 값은 비밀이 아니다**(모든 Expo 앱이 저장소에 커밋한다). 알려주시면 제가 `app.json` 에 넣는다.

> 🔑 왜 웹에서 만드나 — 같은 일을 하는 `eas init` 은 터미널 로그인이 필요하고,
> **그 로그인은 유호님 자격증명이라 제가 대신 못 한다.** 웹 클릭이 유호님께 더 짧다.

### 2) 액세스 토큰 발급

1. https://expo.dev/settings/access-tokens 접속
2. **Create token** 클릭
3. 이름에 `github-ci` 입력 → 만들기
4. 화면에 나온 긴 문자열을 **복사** — 이 창을 닫으면 다시 볼 수 없습니다

### 3) GitHub에 토큰 등록

1. https://github.com/unmet23-lab/SYNK-talk/settings/secrets/actions 접속
2. **New repository secret** 클릭
3. Name 칸: `EXPO_TOKEN`
4. Secret 칸: 2번에서 복사한 문자열 붙여넣기
5. **Add secret**

### 3-2) 안드로이드 서명 키 만들기 — 웹에서

첫 빌드는 앱에 서명할 키가 있어야 한다. **터미널에서 만들면 대화형 질문이 나와 CI 가 못 만든다** —
그래서 웹에서 미리 만들어 둔다.

1. 프로젝트 화면 → **Credentials** → **Android** → `lab.synk.talk`
2. **Build credentials** → 새로 만들기(Expo 가 대신 생성·보관)

> 🔐 이 키를 잃으면 **같은 앱으로 업데이트를 못 낸다**(스토어가 다른 앱으로 본다). Expo 보관이 안전하다.

### 4) 그 다음은 제가 합니다

- Project ID 를 `app.json` 에 넣고 push → **CI 가 preview 빌드를 자동 실행**
- 나온 **APK 링크**를 드립니다. 폰에 설치해 화면을 확인하실 수 있습니다.
- OTA 채널 배선

> ⚠ **토큰을 저에게 직접 보내지 마세요.** GitHub Secret에 넣으시면 제가 값을 몰라도 CI가 씁니다. 채팅·파일에 붙여넣지 마세요.
> **Project ID 는 반대입니다** — 비밀이 아니라 저장소에 커밋되는 공개 값이라 알려주셔야 합니다. 둘을 헷갈리지 마세요.

## ⛔ 제가 못 하는 것과 그 이유 (물어보실 필요 없게 미리)

| 항목 | 왜 |
|---|---|
| Expo 로그인·토큰 발급 | 자격증명입니다. 제가 값을 보면 안 되고, 보관도 안 됩니다. |
| GitHub Secret 등록 | 같은 이유 — 토큰 값을 필드에 넣는 일입니다. |
| `eas init` 로컬 실행 | 위 로그인이 있어야 돕니다. **토큰이 GitHub Secret 에만 있으면 제 쪽에는 없습니다.** |

**나머지는 전부 제 몫입니다** — 코드·설정·CI·빌드 트리거·결과 확인.

## CI가 지금도 하는 일

`EXPO_TOKEN`이 없어도 push할 때마다 도는 검사:

- `npm test` — 커밋 가드 회귀 29건
- `npm run eval` — 교정 엔진 26문항 (거짓양성 0 아니면 빨간불)

빌드 job은 토큰이 없으면 **조용히 건너뜁니다.** 없는 자격증명 때문에 빨간불이 상시로 켜져 있으면 사람이 빨간불을 무시하게 되기 때문입니다.

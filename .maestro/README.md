# 자동 밟기 (Maestro) — 기기 위에서 실제로 눌러 보는 층

## 왜 있나

이 저장소의 회귀 145벌은 **기기를 안 켠다.** `tests/lib/화면세우기.js` 머리말이 그 한계를
스스로 못박았다 — *「expo-* 를 끌고 오는 화면(말하기·답장·도착확인)은 아직 못 연다 … 그건
실기기 몫이다」*, *「이 통로는 첫 렌더만 본다」*.

그런데 우리 앱의 급소가 정확히 거기다: **녹음**(`expo-audio` + 마이크 권한). 모킹으로 재면
「내가 만든 가짜」를 재게 된다. 눌러 보는 것 말고 방법이 없다.

## 실유저가 0명인데 왜 지금 짓나

유호님이 한국에 계셔서 몽골 실유저 모집이 까다롭다. 그래서 **합성 밟기가 당분간 유일한
관측원**이고, Sentry 와 한 벌로 돈다 — 밟는 것이 없으면 Sentry 에 들어올 이벤트도 0이다.

## 손잡이(testID) 규약

흐름은 **카피가 아니라 손잡이로** 잡는다. 카피 감사가 52곳을 한 번에 바꾼 이력이 있어서,
텍스트로 잡으면 확정적으로 깨진다.

| 접두 | 어디서 오나 | 예 |
|---|---|---|
| `입력-` | `인증화면.칸` 의 `id` prop | `입력-학생번호` |
| `곁길-` | `인증화면.곁길` 의 `id` prop | `곁길-첫등록` |
| `답장-` | **계약 값목록** `교정API.학생응답값` | `답장-채택` |
| 그 밖 | 화면에 직접 박은 리터럴 | `녹음-시작` · `말하기-보내기` |

`답장-` 만 계약에서 오는 이유: 그 값(`채택`·`무시`·`수정`)은 서버와의 계약이라 카피처럼
안 흔들린다. 카피(`답문구[값]`)와 갈라 둔 자리가 그대로 손잡이가 된다.

**손잡이가 사라지면 `tests/자동밟기손잡이.test.js` 가 잡는다** — Maestro CLI 없이, CI 없이.
그게 이 폴더에서 유일하게 자동으로 도는 검사다.

## 돌리는 법

```bash
node tools/앱밟기.js
```

먼저 세울 것:
1. Maestro CLI (Windows 는 WSL 이 필요할 수 있다)
2. 안드로이드 에뮬레이터 또는 USB 기기
3. `MAESTRO_STUDENT_CODE` · `MAESTRO_PASSWORD` — **리허설 DB 의 합성 계정만**
   (`.env` 에 적어도 되고 셸에서 세워도 된다 — `tools/앱밟기.js` 가 둘 다 보고 흐름에 넘긴다.
   이름이 ASCII 인 이유는 관례가 아니라 문법이다: `export MAESTRO_학생번호=…` 는 bash 가
   `not a valid identifier` 로 거절한다 · F501 · 2026-08-17)
4. `eas build --profile 합성밟기 --platform android` 로 구운 앱

> 🔴 **`합성밟기` 프로필이라야 한다.** 그 프로필만 `EXPO_PUBLIC_SYNTHETIC_RUN=1` 을 번들에 박고,
> 그 값이 Sentry 이벤트의 `출처` 태그를 가른다. 다른 프로필로 구운 앱을 밟으면 합성 크래시가
> **실사용으로** 쌓이고 — 그건 나중에 소급으로 못 가른다.
> 기기에서 확인: 설정 → 배포 도착 확인 → 「관측(Sentry)」 = `켜짐 · 합성밟기`

## ✅ 첫 실행 실측 (2026-08-16 · 유호 픽 「안드로이드 스튜디오 에뮬레이터」)

「한 번도 안 돌았다」가 이날 해소됐다. **결과: 3/3 통과**(둘은 첫 판에서 고친 뒤).
예고했던 대로 첫 실행에서 고칠 자리가 나왔고, 그게 이 층의 값이었다.

| 무엇 | 실측 |
|---|---|
| **Maestro on Windows** | **WSL 불필요.** `maestro.zip`(GitHub 릴리스)을 풀면 `bin\maestro.bat` 이 그대로 돈다(2.8.0). JVM 앱이라 JDK 17 만 있으면 된다. |
| 에뮬레이터 RAM | **2GB 로는 안 된다.** RN(Hermes)+Sentry 네이티브+Maestro 드라이버+uiautomator 가 함께 올라가 `waitForAppToSettle` 중 드라이버 gRPC 가 끊긴다(`UNAVAILABLE: End of stream`, 2회 연속 같은 자리). **4GB·heap 512M 로 올리니 그 자리에서 바로 통과.** 증상이 「흐름이 실패했다」로 보여서 흐름을 의심하게 만든다 — 인프라 실패다. |
| 흐름 01 의 가정 | **틀렸다.** 로그인 직후 말하기 화면은 «듣기» 단계로 서고, 편지를 다 듣기 전에는 `녹음-시작` 이 아예 없다. 기기를 못 본 판이 「로그인하면 바로 녹음이 뜬다」고 가정했었다. |
| 흐름 02 (앱의 급소) | **에뮬레이터로는 절반만 잰다** — 아래 「환경이 가르는 것」. |
| Sentry | 기기 위에서 **실제로 섰다.** logcat: `RNSentry: Starting with DSN …` + `Native Integrations […AppLifecycleIntegration…]`. |

### 환경이 가르는 것 — 에뮬레이터로 «잴 수 있는 것/없는 것»

에뮬레이터에는 실제 마이크 소리가 없다. 그래서 녹음은 **항상 무발화로 판정**되고,
앱은 그때 설계대로 「목소리가 안 담겼어요」 카드를 띄운다(정상 동작이다).

- ✅ 잰다: 마이크 권한 · 녹음 시작 · 녹음 중 표시 전환 · 녹음 정지 · **무발화 판정 가지**
- ❌ 못 잰다: **소리가 담긴 뒤의 경로**(확인 카드 되듣기 → 보내기 → 서버 도달)

그래서 `02_녹음제출.yaml` 은 두 갈래를 다 받는다. ⚠ **그 흐름의 「통과」는 두 뜻이다** —
어느 쪽을 쟀는지는 실행 로그의 `Run flow when …` 줄이 말한다. 통과만 보고 「제출까지
닿았다」로 읽지 않는다(분모 규칙). ㉠을 재려면 실기기가 필요하다.

### 노트북에 환경을 세우는 순서 (다음 세션이 반복하지 않게)

세 번을 긴 빌드 끝에 「SDK 조각이 없다」로 깨뜨렸다. **필요한 것을 먼저 다 깔고 시작한다.**

```
sdkmanager "platform-tools" "emulator" "platforms;android-35" "platforms;android-36" \
           "build-tools;35.0.0" "build-tools;36.0.0" "system-images;android-35;google_apis;x86_64" \
           "ndk;27.1.12297006" "cmake;3.22.1"
```

- **설치 완료 판정은 폴더 유무가 아니라 `source.properties` 실재로 한다** — sdkmanager 는
  받기 «전에» 폴더부터 만든다. 폴더를 보고 빌드를 던져 21초 만에 깨졌다.
- APK 는 EAS 클라우드 대신 로컬로 굽는다 — 이 계정의 EAS 큐 대기가 **2.4시간**으로 찍혀 있다.
  `npx expo prebuild --platform android` → `gradlew assembleRelease`(release 는 debug 키로 서명된다).
- 굽기 전 `SENTRY_DISABLE_AUTO_UPLOAD=true` — 소스맵 업로드는 org 슬러그·토큰이 있어야 하고,
  없으면 빌드가 거기서 죽는다. 업로드는 「스택트레이스를 사람이 읽게」 하는 층이라 축이 다르다.

### 🔴 그래도 «안 잰» 것

- **Sentry 웹에 이벤트가 실제로 쌓였는지는 이 저장소에서 못 본다** — 조회에 auth 토큰이 필요하고
  없다. logcat 이 증언하는 것은 「SDK 가 DSN 을 들고 섰다」까지다. 그 둘은 다른 층이다.
- `tests/자동밟기손잡이.test.js` 가 초록인 것은 **「부르는 이름이 화면에 있다」까지**다.
  그것을 「자동 밟기가 돈다」로 읽지 않는다.

## 아직 «안 지은» 흐름 (화면 경로를 직접 못 봐서 지어내지 않았다)

- **동의 없음 차단** — 동의 게이트가 어느 화면 어느 단계에 서는지 확인 후
- **오늘 과제 빈 상태** — 빈 상태 화면의 손잡이 확인 후
- **오프라인 → 재연결 → 제출** — Maestro 의 네트워크 제어 명령이 이 기기에서 실제로 먹는지
  확인 후 (`02_녹음제출.yaml` 은 지금 온라인 경로만 밟는다)
- **제출이 서버에 닿았는지** — `도착확인` 화면의 「못 보낸 것」 수를 읽는 단계

## 격리 규칙 (안 지키면 이해 대장이 오염된다)

- 리허설 DB 만. 운영 계정·운영 프로젝트는 밟지 않는다.
- 합성이 만든 데이터는 **골든셋에 자동 편입하지 않는다**(기존 🚫 그대로).
- 합성 밟기로 잴 수 있는 것은 **배선이 섰나**까지다. 「엔진이 학생 성향을 파악하나」는
  못 잰다 — 합성 학생의 성향은 내가 넣은 값이라 그걸 되읽으면 동어반복이다.

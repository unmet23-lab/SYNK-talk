# 문항 검수 — 쓰는 법 (발전 트랙 ① · 유호 확정 2026-08-14)

TOPIK 팩 100문항을 **한 장씩** 확정한다. 확정된 문항부터 라디오 라운드에 설 수 있다.

## 여는 법

```bash
node tools/문항검수.js
```

그다음 브라우저에서 `http://localhost:8438` 을 연다. 끝낼 때는 터미널에서 `Ctrl+C`.
지금 몇 건 섰는지만 볼 때:

```bash
node tools/문항검수.js --현황
```

## 화면에서 하는 일 (한 문항에 한 번)

1. 문항·보기 4개가 뜨고 **정답 자리가 코랄 면**으로 표시된다.
2. 볼 것은 둘 — **정답이 정말 하나뿐인가** · **문장이 자연스러운가**.
3. 「오답이 죽는 이유」 범주가 **미리 눌려** 있다(스킬로 낸 초안). 맞으면 그대로, 아니면 바꾼다.
4. `Enter` = 확정 · `R` = 반려(사유를 적는다) · `S` = 건너뛰기(뒤로 미룸) · `1~4` = 범주.

확정할 때마다 즉시 저장된다 — 중간에 창을 닫아도 그때까지가 남는다.

## 저장되는 곳

`contents/토픽퀴즈검수장부.json` — 문항id마다 `{확정, 범주, 지문, 확정시각, 검수자}`.
git 으로 공유되므로 강사가 검수한 결과가 그대로 배포에 실린다.

## 알아둘 것 셋

- **문구를 고치면 그 문항의 검수는 자동으로 무효**가 된다(확정 당시 지문과 대조 — `낡음`).
  다음에 화면을 열면 그 문항이 다시 줄에 선다. 「검수 완료」 표식이 고쳐진 문항 위에 앉지 않는다.
- **범주는 학생 화면에 나갈 한 벌 문구를 고르는 일**이다(문항마다 해설을 쓰는 게 아니다).
  그래서 몽골어 번역·검수는 100줄이 아니라 **범주 4줄**이면 끝난다 — 그 4줄이 서기 전까지
  오버레이는 한국어만 낸다(지어낸 번역을 방송에 내보내지 않는다).
- **반려는 지우는 게 아니라 사유를 남기는 것**이다. 장부에 무슨 일이 있었는지가 남는다.

## 라운드 통로가 이 장부를 보는 자리

라운드 생성기(P3 · 아직 없음)는 팩 전체가 아니라 **`검수판정().송출가능` 으로 거른 문항**을
`라디오라운드.라운드선정`·`라디오시즌.시즌라운드선정` 에 넣는다. 판정층은
`lib/토픽퀴즈검수.js` 하나고, 도구는 읽기·쓰기·서빙만 한다.

⚠ 팩 상수 `검수확정`(전체 하나)은 그대로 `false` 로 남겼다 — 이 장부가 그 축을 대체하지
않는다. 어느 축을 볼지는 라운드 통로가 서는 커밋에서 못박는다.

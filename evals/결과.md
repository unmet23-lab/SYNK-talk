# 교정 엔진 평가 (2026-08-03)

프롬프트 `prompts/교정.md` · 픽스처 `evals/픽스처.json`(합성 26문장)

## v1 — 현재

**유호님 결정 반영: 「학생이 묻지 않은 오류까지 고친다」.** 규칙 2가 「최소로 고친다」에서 「틀린 것은 전부 고친다」로 바뀌었고, 그 방침을 재기 위해 복합 오류 6문장(`M01~M06`, 오류 2~3개짜리)을 픽스처에 넣었다.

```
거짓양성  0/5    (맞는 문장을 고친 건수 — 0이어야 한다)
교정 정확  21/21  100%
태그 정확  21/21  100%
전체 통과  26/26
```

재현: `npm run eval`

### 방침을 바꿀 때 채점기도 함께 바꿔야 했다

기대 태그 대조가 `some()`(하나라도 맞으면 통과)이었다. 그대로 뒀다면 **오류 3개 중 1개만 잡아도 만점**이라, 방침을 바꾼 것이 채점에 하나도 반영되지 않는다. `every()`로 바꿨다 — 「전부 고친다」의 기계적 표현이다.

### 규칙 1을 지키기 위해 규칙 3을 새로 세웠다

「전부 고친다」를 그냥 두면 규칙 1(맞는 문장은 고치지 않는다)을 잡아먹는다. 그래서 선을 명시했다 — **「틀림」과 「덜 자연스러움」은 다르다.** 문법·맞춤법·높임이 어긋난 것은 고치고, 틀리지 않았는데 원어민이면 다르게 말할 법한 것은 오류가 아니므로 두 방침 어디에도 해당하지 않는다. 정상 문장 5개의 거짓양성이 여전히 0인 것이 이 선이 유지됐다는 증거다.

## 🔴 이 수치가 말하지 않는 것 — 먼저 읽을 것

**100%는 상한이지 실측이 아니다.** 픽스처를 만든 주체와 출력을 만든 주체가 같다(둘 다 이 세션의 Claude). 정답을 아는 채로 답을 썼으니, 이 점수로 교정 품질을 주장할 수 없다.

구체적으로 세 가지가 아직 안 재졌다.

1. **실제 엔진 경로가 아니다.** 제품에서는 API가 `prompts/교정_v0.md`만 보고 답한다. 여기서는 대화 세션의 모델이 픽스처 설계 의도까지 아는 상태로 답했다. **이 차이가 결과를 바꿀 수 있다** — API로 같은 프롬프트를 돌리면 점수는 내려가는 쪽이 정상이다.
2. **오류 분포를 모른다.** 유형별로 1개씩 균등하게 만들었지만, 실제 몽골 학생은 특정 유형에서 압도적으로 많이 틀린다. 어디에 힘을 쏟을지는 실학생 문장으로만 알 수 있다.
3. **거짓양성 0은 「내가 예상한 함정 5개」를 피했다는 뜻**이다. 진짜 위험은 설계자가 예상하지 못한 함정이다.

## 그래서 실제로 증명된 것

- **하네스가 돈다** — 픽스처 → 출력 → 기계 채점 → 종료코드. 프롬프트를 고칠 때마다 같은 20문장으로 이전 버전과 비교할 수 있다. 이게 이번 작업의 진짜 산출물이다.
- **태그 어휘가 수집층과 붙는다** — 23종을 SYNK-appsscript `HW_ERROR_TAGS`에서 그대로 가져왔다. 갈라졌다면 2년치 집계가 깨진다.
- **채점을 세 축으로 나눈 것이 값을 했다** — 합산 점수 하나였다면 거짓양성이 탐지율에 묻힌다. 제품에서 더 나쁜 실패는 「맞게 쓴 학생 문장을 고치는 것」이다. 학생이 자기가 뭘 아는지 모르게 되고 첨삭을 믿지 않게 된다.

## 관찰 1건 — 최소 수정과 교육적 교정이 부딪힌다

`E12` "우리 선생님은 한국어를 잘 배워요"에서 프롬프트 규칙 2(**최소로 고친다**)를 따르면 `가르쳐요`가 맞다. 그런데 실제 교사는 `가르치세요`로 고친다 — 선생님이 주어일 때의 주체 높임이 한국어에서 중요한 교육 지점이기 때문이다. 출력은 후자를 골랐고 태그가 하나 늘었다(`높임:주체` 추가).

**어느 쪽이 옳은지는 교육 방침의 문제이지 엔진의 문제가 아니다.** v1에서 프롬프트에 명시해야 할 첫 항목으로 남긴다 — 「학생이 묻지 않은 오류까지 고칠 것인가」.

## 다음에 할 것 (순서대로)

1. **실학생 문장 20개** — 유호님 또는 강사. 이걸 넣는 순간 위 3가지 한계 중 2개가 사라진다.
2. **API 경로로 실행** — `ANTHROPIC_API_KEY`가 붙으면 대화 세션이 아니라 실제 엔진으로 같은 픽스처를 돌린다. 그때의 점수가 **첫 진짜 기준선**이다.
3. **독립 채점** — 픽스처 정답을 보지 않은 채점자(다른 세션 또는 사람)로 한 번.
4. 그 뒤에야 v1 프롬프트를 손댄다. 기준선 없이 프롬프트를 고치면 나아졌는지 알 수 없다.

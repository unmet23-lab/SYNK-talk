## 지금 상태 — 0일차

**코드는 0줄이다.** 이 커밋에 있는 것은 지침과 가드뿐이다.

그렇게 한 이유: SYNK-appsscript에서 난 사고 4건(커밋 범위 오염 · 자격증명 노출 위험 · 미커밋 파일 소실 · CRLF 혼입)이 **전부 「첫 커밋에 없던 것」** 때문이었다. 프로즈로 다섯 번 막으려다 실패한 뒤에야 기계로 옮겼다. 그 순서를 반복하지 않는다.

| 있는 것 | 무엇 |
|---|---|
| `.githooks/pre-commit` | 자격증명·비밀·대용량·ignore 강제추가 차단 (어느 AI 도구가 커밋하든 걸린다) |
| `tools/guard.js` | 검사 순수함수 — 픽스처로 못박힌다 |
| `tests/guard.test.js` | 순수함수 회귀 23건 (차단 15 · **통과 8** — 거짓양성을 같은 무게로) |
| `tests/precommit.integration.test.js` | git 호출부 회귀 6건 (임시 저장소를 매번 새로 만든다) |
| `.gitignore` · `.gitattributes` | 자격증명 격리 · LF 통일 |
| `docs/` | 이 저장소 규약 + 공용지침(생성물) |

## 교정 엔진 (승부처)

`prompts/교정.md` — 프롬프트 정본. `evals/` — 픽스처 26문장 + 채점기.

```
npm run eval
```

첫 **API 실측** 기준선(2026-08-12 · 합성 102문항 · claude-sonnet-5) = 전체 통과 **80/102** · 거짓양성 2/40 · 교정 79% · 태그 82%. 옛 「26/26·거짓양성 0/5」은 대화 세션이 손으로 쓴 출력이라 상한이었고, API 는 정답을 모른다 — 그 낙차가 처음 측정된 것이 이 값이다. 🔴 **그런데 같은 입력을 세 번 돌리면 판정이 13% 뒤집힌다**(3회차 실측 · 태그 축 9%가 그중 큰 몫 · 갈리는 자리는 «답이 여럿 성립하는» 5문항에 몰린다) — 그 폭 아래의 판 간 차이는 **판정 불능**이다. 온도로는 못 줄인다(이 모델은 비기본 샘플링 파라미터에 400). 숫자를 인용하기 전에 [`evals/결과.md`](evals/결과.md)를 읽을 것.

## 앱 실행

```
npm start        # Expo 개발 서버 (폰의 Expo Go 앱으로 QR 스캔)
npm run web      # 브라우저에서 바로
```

첫 화면은 **배포 도착 확인 화면**이다 — 기능이 아니라 「내가 민 것이 여기 왔는가」를 보는 창이다.

⚠ 4번 이후에 알아야 할 것: **Supabase Cron은 실패 알림이 없다.** Apps Script는 배치가 죽으면 메일을 보냈지만 여기선 조용히 안 돈다 — 배치를 옮길 때 실패 감시를 직접 지어야 한다.

## 브랜드 아이콘

```
node tools/make-icons.js
```

아이콘은 **손으로 그린 그림이 아니라 생성물**이다. 브랜드 정본(SYNK-appsscript `docs/디자인_토큰.json`)의 색이 바뀌면 이 스크립트를 다시 돌린다 — 그림 파일만 교체하는 방식은 다음 개정 때 반드시 낡는다.

바탕 Ink Deep `#080605` · 잉크 Paper `#FBF7F0` · 신호 Coral `#F96859` 1점 · 워드마크 DM Mono 500. (「양모 밤」 · 유호 확정 2026-08-20 · 조항 ⓚ)
`tests/아이콘.test.js`가 **렌더 픽셀**로 검사한다(소스의 hex가 아니라 실제로 칠해진 색).
